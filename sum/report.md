# Sum TTIR 优化与消融

来源：FlagGems全量两阶段sum，按sqrt(n)选择分块后冻结TTIR；源码/文件baseline的LLVM/PTX/cubin一致。最终single对n≤16384使用一个CTA直接写out，其余保留原两阶段。 上游源码：[Sum](https://github.com/flagos-ai/FlagGems/blob/ef8aea78fed8321c3e02a15bf31e847cd0579e4f/src/flag_gems/ops/sum.py)（链接固定到实验使用版本）。

环境：官方Triton3.7.0/H100，连续一维FP32，4 warps / 3 stages / 1 CTA，30点，7轮20ms。完整设备序列计时；该优化改变输出绑定、启动配置和kernel数量。预分配CUDA graph设备时间，不含分配、编译和CPU launch。

**最终平均加速比：算术平均1.423859×，几何平均1.356914×。** 共30个shape，A级证据。

优化方法与性能提升：

1. **小输入由单CTA完成第一级归约。** 保留第二个拷贝kernel时为0.9991×。

   ```diff
   - # 多个CTA各写一个局部和
   - sum_kernel_1[(num_blocks,)](../X, partial, N, BLOCK, ...)
   + # n<=16384：一个CTA覆盖全部输入，但仍输出到partial
   + sum_kernel_1[(1,)](../X, partial, N, triton.next_power_of_2(N), ...)
     sum_kernel_2[(1,)](../partial, Y, 1, ...)
   ```

   减少局部结果和第二级归约的数据量，但两个短kernel的启动及调度成本依然存在，因此仅改变第一级归约方式没有得到可靠整体收益。

2. **直接写出结果并移除第二个kernel。** 累计1.3569×；小输入15点1.8402×；直接配对增量1.3575×。

   ```diff
   - sum_kernel_1[(1,)](../X, partial, N, BLOCK, ...)
   - sum_kernel_2[(1,)](../partial, Y, 1, ...)
   + sum_kernel_1[(1,)](../X, Y, N, BLOCK, ...)
   ```

   第一级已经得到全量和，直接写最终输出即可省去第二次kernel执行与中间结果读写。小输入计算短，移除这次启动/调度的相对收益更突出；n>16384保留原两阶段。

3. **32位索引与分组归约对照。** i32为0.9995×，分组归约0.9997×，两者组合0.9972×，未加速。

   ```diff
   - pid = tl.program_id(0).to(tl.int64)
   + pid = tl.program_id(0).to(tl.int32)
   - total = tl.sum(values, 0)
   + partial = tl.sum(tl.reshape(values, (4, BLOCK // 4), can_reorder=True), 0)
   + total = tl.sum(partial, 0)
   ```

   i32尝试降低整数地址运算开销，分组尝试改变归约树与线程间通信。这两种变换在当前配置上没有可靠整体收益，不能因为逻辑上少了宽整数或改变了树形就推断硬件执行更快。

4. **加载缓存策略对照。** .cg为0.9429×；TTIR中的加载.cs对照为1.0001×，均未采用。

   ```diff
   - values = tl.load(ptrs, mask, other=0)
   + values = tl.load(ptrs, mask, other=0, cache_modifier=".cg")
   ```

   .cg让加载优先使用L2及以下缓存，可能减少L1干扰，也可能损失有效复用，本例出现回退。公开Triton的tl.load不接受.cs，不能伪造对应源码调用；该TTIR属性对照与默认加载的机器码一致，未形成有效优化。

5. **完整CTA使用无mask加载。** 相对原始基线0.9945×。

   ```diff
   - values = tl.load(X + offsets, offsets < N, other=0)
   + if (pid + 1) * BLOCK <= N:
   +     values = tl.load(X + offsets)
   + else:
   +     values = tl.load(X + offsets, offsets < N, other=0)
   ```

   只有确认整块都在输入范围内时才去掉mask，尾块仍检查边界。意图是减少谓词和索引判断，但新分支及编译布局也有成本，当前矩阵未观察到整体改善。

6. **在最终版上组合大输入无mask分支。** 相对最终版增量0.9998×，未采用。

   ```diff
   - # 大输入沿用原来的带mask两阶段路径
   + # 大输入完整块走无mask加载，尾块和小输入最终路径保留
   + if full_block:
   +     values = tl.load(X + offsets)
   ```

   该对照检验无mask加载能否在已有单kernel小输入优化之外继续受益。结果接近1×，说明它没有补足当前最终版的主要性能瓶颈，不把这项加入正式组合。

数值、编译链、memcheck/racecheck通过；n>16384路径没有算法改动，接近1×的变化为计时波动。不能称作保持原kernel数和固定启动契约下的纯TTIR收益。
