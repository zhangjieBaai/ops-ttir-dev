## 唯一改动与同链路检查

- baseline 为原始 sum_kernel_1/2 及 program_id 函数体；只提取计算函数、去掉 libentry 主机装饰器并隔离依赖。AST 检查确认计算不变，源码、完整上游快照、commit 和 SHA256 已保存。
- 原实现按 sqrt(n) 选分块，没有 autotune。逐点真实导出形成 39 组 TTIR；同组实际内容及完整 options 相同才复用。baseline 在候选生成前已完成源码→TTIR→设备执行、精度和基线计时并 Git 冻结（`e9212c9`）。
- 逐 30 shape 的源码 TTIR 与冻结文件字节一致，规范化 TTGIR 一致，LLVM/PTX/**完整 cubin 字节一致**；源码/文件两个中间和最终输出逐位一致。
- 所有候选只修改 TTIR。i32 将有界非负偏移从 i64 缩窄；cg/cs 修改 load 属性；fold 将宽归约 reshape 为 4×width/4 后两级归约；组合叠加 i32 与 fold。没有改 kernel Python、TTGIR、LLVM、PTX 或 cubin，也没有内联汇编。
- baseline/候选均经同一 triton.compile(TTIR文件) 入口、官方原生后端、CompiledKernel 加载、同一个两阶段 launcher，完整 options/SM90 target 一致。文件入口从 make_ttgir 继续，不重跑 Python 前端或 make_ttir。
- 签名、grid、工作区、映射、两个 kernel 序列均保持一致；主机 launch 不调用 PyTorch compute。测试侧允许 PyTorch 生成输入和计算参考。

## 精度与内存检查

6 版（baseline+5候选）各83个用例，共498次检查通过：30个随机性能点、边界压力分布、NaN/±Inf分类；同时检查 CPU FP64 与原生 ATen 参考、每个中间部分和、sentinel覆盖、mid/out尾部canary及输入未写。

有限值标准为 `abs(error) <= 2e-5 + 2e-6 * sum(abs(x))`，是 L1 范数缩放标准，不能描述为紧输出相对误差。各版最大输出绝对误差 225.4124756（大尺寸 large-offset 输入）；最大输出误差/允许界为 0.0223454。原基线中间部分和最大绝对误差0.7811279，fold版0.6837158。所有逐点、逐分布实际误差留在 accuracy.json。

baseline、i32、i32+fold 三版在30个随机shape分别完成 memcheck 和 racecheck（各90次算子调用）：[memcheck](results/runs/final/memcheck.log) 0 errors；[racecheck](results/runs/final/racecheck.log) 0 hazards、0 errors、0 warnings。sanitize未额外运行全部53个压力分布，因此不宣称全部分布均经过sanitizer。

## 设备、计时边界与限制

固定 `/root/venvs/ir-ops-dev/bin/python`、Python3.12.3、官方Triton3.7.0、PyTorch2.12.0+cu130。环境核查包括实际 Python/Triton/libtriton 路径、分发信息、wheel RECORD、后端/libtriton/ptxas/libdevice哈希、动态库加载路径与相关环境变量。RECORD仅核对本地安装记录，不等于远程官方wheel独立来源认证。

最终使用GPU6，UUID `GPU-c93dcf8b-2363-d1c2-02b4-4572cef79c41`，H100 80GB HBM3。GPU7初始计时被另一logsumexp任务干扰而**整轮无效**，已保留旧数据；[迁移协议](results/runs/gpu6_baseline/protocol.json)明确仅变更设备分配，全部主实验在GPU6同卡重新运行。没有混用两张卡的性能样本。

指标为预分配mid/out的两个kernel总CUDA graph replay设备耗时，不含Python launch、分配、编译、加载。编译/加载/预热在计时前完成。不清缓存、不主动锁时钟；记录了[设备状态](results/runs/round1/gpu_state.txt)，不能声称冷缓存或锁频测试。主测与复测同点baseline耗时比范围约0.9908–1.0164，中位约1.0027；跨进程漂移与候选的千分级差异同量级。

初筛11点、其余19点用于分阶段transfer检查；近邻shape存在跨集合泄漏，**不是独立holdout**。计划中的“近邻整组划分”措辞过强，采纳审查意见在此更正，不改写冻结协议或历史证据。没有根据19点结果再改候选。

## 后端观察与停止理由

最大分块stage1（B=8192）baseline 56寄存器/0spill/16B shared，i32为32/0/16，fold为56/0/16，i32+fold为40/0/16。两次bar.sync数量没有下降。baseline已生成ld.global.v4.b32；i32改变谓词/地址整数宽度，fold改变局部加法依赖，但这些静态变化没有转化为实测整体收益。cg在 n=16777215 初筛退步到0.623685×。

[资源记录](results/runs/round1/static_resources.json)只支持静态观察；没有NCU运行，未测achieved occupancy或stall占比，不将其当作已证明的因果。前三个近零收益方向后已按KernelForge记录[反思](results/runs/round1/reflection.json)，停止同类参数搜索。改变grid、分块公式或融合两次launch需另建匹配baseline实验，不属于本轮固定契约。
