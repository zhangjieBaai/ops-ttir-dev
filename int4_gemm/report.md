# INT4 反量化融合 GEMM TTIR 优化

来源：FlagGems 的 INT4 反量化融合矩阵乘实现。基线已在同一设备 kernel 中融合 INT4 解包、分组反量化和 Tensor Core GEMM，不以先完整反量化再矩阵乘作为性能基线。 上游源码：[INT4 融合矩阵乘](https://github.com/flagos-ai/FlagGems/blob/ef8aea78fed8321c3e02a15bf31e847cd0579e4f/src/flag_gems/ops/_weight_int4pack_mm_with_scales_and_zeros.py)（链接固定到实验使用版本）。

环境：官方Triton3.7.0，H100，A/scale/zero及输出FP16、packed权重uint8，FP32累加；group=128，K为128倍数、N为16倍数，M允许尾部。逐shape固定原tile/warps/stages，1 CTA，新增点沿用原配置族，非全面autotune。预分配CUDA graph设备计时，不含分配、编译或CPU launch，配对计时与A/A检查通过。

优化方法与性能提升：

1. **首轮组合：共享low/high组参数、标量化组索引、非负索引unsigned。** 增量1.083768×、累计1.083768×。

   ```diff
   - group_low = (k0 + 2 * kp) // qGroupSize
   - group_high = (k0 + 2 * kp + 1) // qGroupSize
   - scale_high = tl.load(S + group_high[:, None] * stride_sg + ns[None, :], mask_n)
   + group = (k0.to(tl.uint32) // qGroupSize.to(tl.uint32)).to(tl.int32)
   + scale_high = scale_low
   + zero_high = zero_low
   ```

   一个byte中的两个nibble以及当前对齐K tile共享同一量化组，复用scale/zero并标量化组索引，减少重复地址和组参数计算；unsigned索引为非负范围的除余简化提供条件。这三项是首轮组合，没有将收益独立分配给某一个指令变化；FP32减乘与FP16舍入顺序保留。

2. **缩窄scale/zero加载后广播。** 增量1.958765×、累计2.122819×。

   ```diff
   - groups = tl.full((BK // 2, 1), group, tl.int32)
   - scale = tl.load(S + groups * stride_sg + ns[None, :] * stride_sn, mask_n)
   + scale_row = tl.load(S + group * stride_sg + ns * stride_sn, ns < N)
   + scale = tl.broadcast_to(scale_row[None, :], (BK // 2, BN))
   ```

   将重复的K×N逻辑参数加载改成一行N元素加载后广播，zero同样处理。既减少冗余参数索引和加载表达，也缩小需要维护的地址/参数向量，可能改善后端加载与寄存器分配。它不意味着硬件DRAM读取字节必然按逻辑张量大小同比减少，缓存和广播原本也可能消除部分重复。

3. **再删除契约内恒真的K mask。** 增量1.039553×、累计2.206938×。

   ```diff
   - a = tl.load(a_ptrs, (ms[:, None] < M) & (ks[None, :] < K), other=0)
   - packed = tl.load(w_ptrs, (ns[None, :] < N) & (byte_idx[:, None] < K // 2), other=0)
   + a = tl.load(a_ptrs, ms[:, None] < M, other=0)
   + packed = tl.load(w_ptrs, ns[None, :] < N, other=0)
   ```

   K为128倍数且BK为64或128，当前K迭代不会越界，可以去掉恒真的K侧谓词。M/N尾部mask仍保留。该改动尝试减少比较和谓词组合，单独启用几乎无整体收益，在窄加载上下文中才取得表述的条件增益，说明它与加载lowering存在交互。

4. **再加BK64的128-K组内参数复用。** 增量1.111385×、累计2.451211×。

   ```diff
   - for k0 in range(0, K, 64):
   -     # 每次重新加载当前group的scale/zero并执行一次dot
   + for k0 in range(0, K, 128):
   +     # 每个128-K组只加载一次scale/zero
   +     for half in tl.static_range(2):
   +         k_start = k0 + half * 64
   +         # 加载A/packed，按共享参数反量化，依原顺序执行dot
   ```

   两个64-K迭代属于同一量化组，将组参数保留到第二次dot使用，减少组参数重复加载与索引计算。两次dot的先后和FP16反量化舍入不变；BK128路径不需要重复合并，保持原状。复用会延长参数存活，因此收益需由完整融合kernel验证，不能仅按参数加载次数推算。

5. **再将group128除法替换为右移7位（最终版）。** 增量1.030917×、累计2.527885×。

   ```diff
   - group = k0.to(tl.uint32) // qGroupSize.to(tl.uint32)
   + group = k0.to(tl.uint32) >> 7
   ```

   量化组大小固定128、k0非负，除128可用逻辑右移7位表达，降低运行时整数除法及其依赖开销。该特化只在既定group=128合同内合法，不扩展到任意分组大小。


条件收益不能相加。增量相对前一版本，累计相对原始基线，各项存在依赖和交互。

首轮三项是组合对照，未独立分摊其内部贡献。K mask单独启用只约0.2%平均增益，在窄加载后约3.9%，显示交互；保留原FP16反量化舍入和dot累加次序；参考FP32 matmul atol=0.035/rtol=0.003。

全部时间、加速比和方法收益使用同一组原始配对样本；冻结最终选择不变。新增中间消融未全部重跑sanitizer，最终版沿用已有通过记录。
