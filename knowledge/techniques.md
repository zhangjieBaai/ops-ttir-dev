# 技术目录

每项含：做什么、怎么改 TTIR、证据等级、代价与适用条件。
等级定义见 [README](README.md#证据等级)。

---

## T1. 去除 loc 调试属性

**做什么**：删掉 `#loc` 定义与行内 `loc(...)`。文件 210 行 → 93 行。

**改法**：见 `layer_norm/make_candidates.py` 的 `without_locations()`。

**证据**：C 级静态哈希：`canonical` 候选 ELF `.text` 与 baseline 相同；B 级初筛计时约 1.000×（6 点、3 轮、rep=30ms，`results/screening.json`），没有该候选的完整矩阵独立复测。

**代价**：零。但**零收益**——不要算进优化成绩。

**用途**：可读、可 diff；可以只对比较副本去 loc，冻结原件与来源映射保留。完整 cubin 哈希可能因调试信息改变，只有 `.text` 相同，报告时要写清。

## T2. 按尺寸分派 tile 宽度（最强杠杆）

**做什么**：用 `scf.if` 按运行时 N 选择张量宽度，每档配一个窄 tile 的展开副本。

**改法**：`make_candidates.py` 的 `dispatch()`。嵌套结构：

```mlir
%fits0 = arith.cmpi sle, %N, %limit0 : i32
scf.if %fits0 {
  // tensor<1024xf16> 版本
} else {
  %fits1 = arith.cmpi sle, %N, %limit1 : i32
  scf.if %fits1 { ... } else { ... }
}
```

**证据**：`tile_dispatch_v2` 几何 1.288×（B，完整 30 shape、7 轮，未独立复测此候选）；`tile_dispatch_math_v2` 几何 1.293×（A，30 shape、7 轮、独立复测 1.294×）。

**代价**：
- 代码体积按档位数倍增（5 档 → 553 行）
- 宽分支可能抬高整个 kernel 的统一寄存器资源额度，见 T11
- 每档要处理"分支局部常量尺寸匹配"，见 [failure-patterns](failure-patterns.md#f1-分支内张量宽度与外部零常量不匹配)

**适用条件**：N 分布集中且可枚举；有明确的运行时判别条件；基线对每个 N 都在做大量无效工作。

**边界**：分派是否划算取决于各档实际工作量、输入分布、代码体积和整体资源；N 不规律本身不是失效证据。不得把 LayerNorm 的收益排序推广为所有算子的“最强杠杆”。

## T3. 窄 tile 循环（省寄存器，但会在大 N 崩）

**做什么**：把 `tensor<8192xf32>` 累加器换成 `tensor<1024xf32>`（或 2048），循环次数相应增加。

**改法**：改 `arith.constant` 的 tensor 尺寸、`tt.make_range` 的 end、`scf.for` 的 step。

**证据**：B 级。寄存器从 60 降到 32（`results/round2/compile_v2.json`）。

| 候选 | 宽度 | 初筛 geo | 最差 |
|---|---:|---:|---:|
| r2_loop1024 | 1024 | 1.2570 | **0.7836** |
| r2_loop2048 | 2048 | 1.2233 | **0.7508** |

**观测**：本批两个候选在大 N 初筛回退到约 0.75–0.78×。循环次数增加是机制假设，尚未单独消融其成本。

**可尝试配 T2**：`r2_fine1024_reload` 初筛最差 1.0124，对 baseline 未观测到中位数回退；它还改变展开和 load 行为，不能把收益只分配给分派，也不代表全面优于 parent。

## T4. 显式重载（检查加载是否保留）

**做什么**：强制重新 load 某个值，而不是让后端复用长存活期的旧值。

**改法**：初版用 volatile load。`optimization_plan_v2.md` 记录 PTX 里出现 volatile；在对应 NCU 对照中 long-scoreboard/issue 从 5.67 升到 18.90，大 N 相对 parent 更慢。这是相关性，未隔离 volatile 的独立计时贡献。

**后续候选**：`r2_fine2048_ca` 把 mean load 改为 `.ca` 普通 load；不同属性在本版本可能阻止某些公共子表达式合并。**`.ca` 是缓存提示，不是通用的“禁止 CSE”语义。** 必须逐阶段确认实际 load 数、资源和计时。

**证据**：B 级。
- `r2_fine1024_reload`：初筛 1.4060，最差 1.0124，40 regs
- `r2_fine2048_reload`：初筛 1.4445，最差 1.1076
- `r2_fine2048_ca`：初筛 **1.4901**（本库最高初筛值），最差 1.1439

**适用边界（C 级）**：独立双 load 探针显示，默认属性被合并成一条 PTX load；默认/`.ca` 混用保留两条；volatile 保留 volatile load。该结果仅验证此编译器和探针，不能保证所有程序都保留两次读取。volatile 约束优化，不表示每次都访问 DRAM，也不能据这些不同进程的初筛数字给两种机制做最终排名。详见 [核查证据](evidence-index.md#kernelforge-知识核查)。

**代价**：多一次内存访问。只在"复用导致值存活过长、抬高寄存器"时才划算。

## T5. 算术表达式改写（收益小）

**做什么**：
- 倒数复用：两处 `divf x, N` → 一个 `divf 1.0, N` + 两次 `mulf`
- `math.sqrt` + `arith.divf` → `math.rsqrt`
- 显式 `mulf`/`subf` 促成 FMA

**证据**：B 级，`arithmetic` 候选初筛 1.009×（6 点）。

**边界**：本次初筛约 1%，不能作为其他算子的收益预期。倒数、rsqrt、FMA 改写会改变舍入和误差传播，需验证各自的数值压力输入。

**注意**：本版本张量 `arith.negf` 在 `ConvertTritonToTritonGPU` 阶段失败；不是解析器拒绝所有 negf。用 `-0.0 - x` 修复时要检查符号零，不能随意换成 `+0.0 - x`，见 [failure-patterns](failure-patterns.md#f2-arithnegf-未通过文件入口-lowering)。

## T6. 延迟 store 统计量

**做什么**：把 `Mean`/`Rstd` 的 store 推到输出阶段之后，让三个阶段对 X 的加载有机会被 CSE 合并。

**证据**：B 级，`r2_delay` 初筛 1.4017，最差 1.2021，**但 80 regs / 4 spills**。

**代价**：值存活期变长 → 寄存器压力上升。`r2_delay_affine_v2` 组合后回退到 1.2008，最差 0.9600。

**适用条件**：无别名契约下才合法（当前契约满足）。

## T7. reshape + reduce 折叠累加器

**做什么**：保持宽加载，但把累加器折窄。

```mlir
%v22 = tt.reshape %v21 : tensor<8192xf32> -> tensor<4x2048xf32>
%fold = "tt.reduce"(%v22) <{axis = 0}> ({...addf...}) : (tensor<4x2048xf32>) -> tensor<2048xf32>
```

**证据**：B 级，`r2_fold2048` 初筛 1.2493，最差 1.0301，无回退。全文仅 107 行。

**本轮结果**：初筛未优于分组分派/重载候选，未进入最终选择；不能据此断言比所有直接窄加载都慢。它提供了另一种表达：加载宽度与累加宽度解耦。

**适用条件**：希望解耦加载和累加宽度；宽张量不自动保证更好的向量化，仍须检查 layout、对齐和最终 load 指令。

## T8. 循环结构改分组宽度

**做什么**：把三遍 8192 宽的动态循环改成 1024/2048/4096 宽的固定分组循环。

**证据**：B 级，`r2_loop*` 系列 32–40 regs / 0 spill，但性能见 T3 的告警。

**代价**：可能增加循环控制开销。分派（T2）是可试路线，需验证边界与大 N。

## T9. 显式 cache modifier

**做什么**：`tt.load` 上加 `cacheModifier`。

**证据**：B 级，`r2_fine2048_ca` 1.4901（见 T4，与重载机制耦合，不能单独归因于 cache modifier 本身）。

**最终记录**：`.ca + .cs` 的 `r2_fine2048_stream` 完整30点几何1.4322×（B，未独立复测），再加小N混合分组的 `r2_mixed_stream` 为1.4397×，独立复测1.4395×（A）。这支持组合，不是`.cs`独立收益。第一次同时包含`.ca`与`.ca+.cs`的测量因基线漂移被整轮弃用，目前没有有效的完整同会话消融；不得选取弃用数据的有利点。`.lu` load 在本库没有验证记录。见[第二轮复盘](layernorm-round2.md#e4-缓存提示要随数据用途设计但单项收益需要单独对照)。

## T10. 单 tile 展开（基础版）

**做什么**：把三遍循环各展开成一次，仅当 N ≤ BLOCK_SIZE。

**证据**：B 级，`single_tile` 初筛 1.196×，64 regs / 0 spill。

**意义**：该展开候选初筛比 baseline 快约 20%；变化还会影响 CSE 与 lowering，不能把全部收益归因于“循环指令消失”。适用范围必须由分支保护或测试契约保证。

## T11. 控制特化分支的寄存器预算

**做什么**：不是独立技术，而是 T2 的必要配套。

**问题**：本轮常规 kernel 使用统一寄存器资源额度，宽分支可能抬高各路径的资源成本；最终额度不是各分支独立编译值的精确最大值。

| 版本 | 寄存器 | spill | 理论 occupancy |
|---|---:|---:|---:|
| baseline | 60 | 0 | 50.0% |
| tile_dispatch_math_v2 | **80** | **2** | **37.5%** |
| r2_loop1024（单窄） | 32 | 0 | — |

**做法**：用"逻辑宽度 / (warps×32)"粗估活跃状态，再查看编译后的 registers/shared 与 occupancy API 结果。若实测跨档，考虑：
- 把最肥分支也窄化（可能需改算法）
- 去掉该分支
- 接受档位下跌，但要用测量证明收益仍为正

**反例参考**：v1 的 80 regs / 37.5% 理论 occupancy 仍观测到约 1.29×，所以 occupancy 不能替代计时。资源变化和性能变化之间仍需消融，不能外推到其他 kernel。

## T12. 分组累加、分组输出与load存活期联合设计

**做什么**：不只缩窄一个tensor，而是一起控制统计量累加状态、输出临时值、分组数量、范围展开和load复用。

**本轮做法**：N≤3072用1024分组，其余用2048；常用范围静态展开，超出范围用动态循环。mean显式`.ca`普通load、variance默认load、Y用`.cs`store。保持中心化方差算法和同一签名/grid/options，不用maxnreg强压资源。

**证据**：整个组合为A：完整30点/7轮几何1.4397×，独立进程30点/5轮1.4395×；parent同轮1.2952×。资源为C：80→48寄存器、spill 2→0；不把全部收益归因于寄存器。来源：[主测](../layer_norm/results/round2/full_stable.json)、[复测](../layer_norm/results/round2/independent_repeat.json)、[资源](../layer_norm/results/round2/resources.json)。

**代价和边界**：代码展开增大，加载次数/循环工作可能增加；相对parent仅22/30点更快，最大回退3.63%。它不是“只要低寄存器就更快”的结论，也不是所有算子都需要三遍遍历或尺寸分派。

**迁移办法**：先画出各阶段同时存活的逻辑状态，再检查实际TTGIR布局、load与资源。用候选分别检验窄化、展开、重载与缓存表达；最终组合重新做C0/C1和全矩阵。细节见[有效经验E1/E2](layernorm-round2.md)。

## T13. 细化小范围，同时保持整个kernel的资源档位

**做什么**：只调整差距集中的尺寸区间，观察整体kernel是否跨寄存器档位，并用区间外用例防止编译布局变化引起退步。

**证据**：B级同会话30点/7轮，`r2_fine2048_stream`→`r2_mixed_stream`，两版均48寄存器/0 spill；N=2560耗时16.526→15.264µs，N=3072为20.340→20.077µs。第一版未独立复测，不能把最终组合的A级证据转给单项收益。来源：[主测](../layer_norm/results/round2/full_stable.json)、[`small_chunk`生成逻辑](../layer_norm/make_round2.py)。

**边界**：这里按N≤3072改成1024分组；其他算子须重新选择阈值。分支外的逻辑不变不保证全局寄存器分配和最终指令布局不变。
