# LayerNorm 前向 TTIR 消融实验

本报告研究已有前向最终版r2_mixed_stream，不是backward dX。原baseline、optimized及冻结教程均不修改。官方Triton3.7.0、H100、FP16、M4096、N1024..15872步长512、固定8 warps/3 stages/1 CTA。

## 逐项加入的条件收益

收益定义为前一版本耗时/后一版本耗时的几何平均。各版本都与共同baseline交错测量，下列差分使用同会话每shape耗时中位数，未声称是直接相邻版本配对；百分比表示吞吐提升，不是耗时减少。

| 对照 | 改动 | 主测加速 / 吞吐提升 | 复测加速 / 吞吐提升 |
|---|---|---:|---:|
| abl_arithmetic → abl_grouped | 窄化为2048并重构三遍动态循环 | 1.1962× / +19.62% | 1.1965× / +19.65% |
| abl_grouped → abl_unroll | 按N范围选择组数并静态展开 | 1.0995× / +9.95% | 1.0991× / +9.91% |
| abl_unroll → abl_ca | 仅均值阶段使用.ca，改变跨阶段load合并 | 1.0667× / +6.67% | 1.0668× / +6.68% |
| abl_ca → abl_cs | 输出使用.cs | 1.0141× / +1.41% | 1.0143× / +1.43% |
| abl_cs → abl_final | N≤3072时改为1024分组 | 1.0049× / +0.49% | 1.0049× / +0.49% |

1/N复用和rsqrt分别以baseline为参照，见第一张表；合并后不是两个百分比相加。“窄分组”同时改变累加/循环的表达，不能进一步把其收益全部归因于寄存器下降。

## 从最终版移除改动

数值为“缺少该改动版本的耗时 / 最终版耗时”，大于1说明最终版更快。这里是给定其余变换后的条件贡献，不是可相加的独立贡献。

| 去掉的变化 | 主测条件加速 | 复测条件加速 |
|---|---:|---:|
| .ca | 1.0675× | 1.0678× |
| .cs | 1.0165× | 1.0166× |
| 小N混合分组 | 1.0049× | 1.0049× |
| 静态范围展开和小N混合（联合移除） | 1.1440× | 1.1438× |

最后一行同时回到统一2048动态循环，不能解释成“只移除展开”的纯独立贡献。展开本身的更干净对照为上一节abl_grouped→abl_unroll。

这些是当前顺序下的条件效应，存在交互，不能相加为总收益。低于约1%且跨轮方向不稳定的差异不据此宣称可靠优化；本实验未给置信区间。没有把历史搜索中未进入最终版的延迟统计量store、volatile或输出affine重写计入最终改动。

资源线索：动态窄分组为32 registers，静态展开为80，加入.ca后为48。这与加载复用/存活范围改变一致，但并未单独证明全部收益由寄存器导致。resources.json的静态load/barrier计数包含所有分支、循环体只计一次，不代表运行时指令总量。
这里.ca既是缓存提示，也在该程序和编译器中改变了load合并及存活范围。因此该消融测到的是整个编译结果变化，不是单纯的L1缓存命中率贡献；公开Triton能写出.ca也不意味着它在任意程序中都能强制保留重载。

## 能否用普通Triton实现

| 改动 | 公开Triton表达 | 结论 |
|---|---|---|
| 倒数复用 | inv=1./N，mean=sum*inv，var=sum*inv | 能 |
| sqrt+除法改rsqrt | tl.rsqrt(var+eps) | 能 |
| 窄分组/动态循环 | tl.arange(0,C)、range/tl.range、向量累加 | 能 |
| 按N范围展开 | 运行时if/elif、constexpr组数、tl.static_range | 能 |
| 均值阶段.ca | tl.load(...,cache_modifier=".ca") | 能；不保证禁止任意CSE |
| 输出.cs | tl.store(...,cache_modifier=".cs") | 能 |
| 小N混合1024/大N2048 | 分支调用constexpr C不同的@triton.jit helper | 能 |

可执行实现：[ablation_triton.py](ablation_triton.py)。源码版覆盖这些最终变化，不是仅凭API名称判断可行；已完成完整数值矩阵、边界检查与性能测试。源码导出TTIR后再走文件入口，与该源码路径LLVM/PTX/cubin逐字节一致。源码版与原手写TTIR的机器码.text哈希不同，因此可表达同一算法不等于同一机器码。

主测：源码版耗时 / 手写TTIR最终版耗时几何比=0.9998；大于1表示手写TTIR更快，小于1表示源码版更快。
复测：源码版耗时 / 手写TTIR最终版耗时几何比=0.9996；大于1表示手写TTIR更快，小于1表示源码版更快。

本例最终优化没有必须依赖普通Triton无法表达的运算。TTIR的优势在精确控制编译截点和实验输入；真实机器码、CSE、寄存器与调度效果仍由下游决定。
