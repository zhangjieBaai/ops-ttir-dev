# LayerNorm backward dX TTIR 优化

来源：官方 Triton v3.7.0 LayerNorm 教程的 dX 计算段，保留两次归约和 dX 写出。基线与优化版都不计算 dW/dB，也不使用梯度累加锁，因此不代表完整融合反向算子的性能。

环境：官方Triton3.7.0/H100，FP16 X/DY/W/DX、FP32计算和保存统计量，N/stride为16倍数、N≤16384；按next-power-of-two固定5个family配置。30点，3轮20ms。预分配CUDA graph设备时间，不含分配、编译和CPU launch。

优化方法与性能提升：

1. **小宽度组折叠冗余mask与中间状态。** 1024/2048组采用，未独立分摊对全矩阵的贡献。

   ```diff
   - w = tl.load(W + cols, mask=mask)
   - centered = tl.where(mask, x - mean, 0.0)
   - wdy = tl.where(mask, w * dy, 0.0)
   + w = tl.load(W + cols, mask=mask, other=0.0)
   + centered = x - mean
   + wdy = w * dy
     # DY的无效位置也加载为0，最终输出store仍保留mask
   ```

   让无效位置的W/DY在加载时为0，使其乘积自然为0，可以省去部分重复select及相关中间向量。这改变谓词计算与值存活，但不删除实际访存边界检查；在已验证的输入和表达式上合法。

2. **4096组按复用特点设置缓存淘汰策略。** 该配置组采用，未独立分摊对全矩阵的贡献。

   ```diff
   - x = tl.load(X + cols, mask=mask, other=0)
   - dy = tl.load(DY + cols, mask=mask, other=0)
   - w = tl.load(W + cols, mask=mask)
   + x = tl.load(X + cols, mask=mask, other=0, eviction_policy="evict_first")
   + dy = tl.load(DY + cols, mask=mask, other=0, eviction_policy="evict_first")
   + w = tl.load(W + cols, mask=mask, eviction_policy="evict_last")
   ```

   X/DY按行流过，W被多行复用；分别提示优先淘汰流式输入、尽量保留权重，尝试改善缓存竞争。这里只说明策略和该配置组的验收结果，没有独立证明命中率变化解释了全部收益。

3. **8192组保留基线。** 该组不增加新优化。

   ```diff
   - # 强制采用其他宽度组的改动
   + # 8192组沿用原始baseline实现
   ```

   不同宽度的归约、寄存器压力和访存比例不同。按完整配置组回退避免将其他组的局部收益外推到此组。

4. **16384组合并统计归约并提取标量系数。** 该配置组采用，完整矩阵仍未达到10%目标。

   ```diff
   - c1 = tl.sum(xhat * wdy, 0) / N
   - c2 = tl.sum(wdy, 0) / N
   - dx = (wdy - xhat * c1 - c2) * rstd
   + s1, s2 = tl.reduce((xhat * wdy, wdy), 0, sum_pair)
   + alpha = (s1 / N) * rstd
   + beta = (s2 / N) * rstd
   + dx = wdy * rstd - beta - xhat * alpha
   ```

   sum_pair按分量相加，将两项统计放在联合归约中；把全行相同的乘法系数提前算成标量再广播。意图是共享归约遍历、减少向量端重复算术和长存活状态，浮点运算顺序变化已按原容差验证。各配置组的贡献未分别对全矩阵消融，最终平均仍使用前表实际选择路径的配对数据。

基线与优化版的编译链一致性、数值压力和计时控制均已独立验证。仅计dX kernel，不包含统计量计算、前向、autograd、dW/dB或完整反向。
