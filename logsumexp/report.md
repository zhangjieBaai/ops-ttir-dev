# Logsumexp TTIR 优化

来源：FlagGems 的 logsumexp 实现，包含内层与非内层归约路径。按原启发式配置导出 TTIR 后优化，基线与优化版共享 Triton 原生编译链和主机接口。 上游源码：[Logsumexp](https://github.com/flagos-ai/FlagGems/blob/ef8aea78fed8321c3e02a15bf31e847cd0579e4f/src/flag_gems/ops/logsumexp.py)（链接固定到实验使用版本）。

环境：官方Triton3.7.0/H100，连续FP16输入输出、FP32指数与累加。输入视为[M,N,K]，沿N归约，K=1为内层、K=64为非内层；原配置族固定，30点，7轮20ms。预分配CUDA graph设备时间，不含分配、编译和CPU launch。

优化方法与性能提升：

1. **缩减无效填充并合并在线指数。** 属于最终组合，未单独分摊收益。

   ```diff
   - new_m = tl.maximum(m, x)
   - z = z * tl.exp(m - new_m) + tl.exp(x - new_m)
   + new_m = tl.maximum(m, x)
   + q = tl.exp(-tl.abs(x - m))
   + z = tl.where(x > m, z * q + 1.0, z + q)
   ```

   有限输入上两个指数中必有一个对应exp(0)，利用最大值的选择关系可将每次更新的两个指数改为一个，减少特殊函数计算；全-inf位置仍需保留单独保护。非内层按N范围缩小tile，减少填充位置的算术和归约工作。

2. **在FP16上求最大值并为长行选择单块归约。** 属于最终组合，未单独分摊收益。

   ```diff
   - x = tl.load(ptrs, mask, other=-float("inf")).to(tl.float32)
   - maximum = tl.max(x, 0)
   + x16 = tl.load(ptrs, mask, other=-float("inf"))
   + maximum = tl.reduce(x16, 0, maximum_half).to(tl.float32)
   + x = x16.to(tl.float32)
   ```

   输入本来就是FP16，maximum_half用tl.maximum选择较大值；在扩展为FP32前完成max，改变归约的数据宽度和中间状态。指数和求和仍用FP32。已验收长行由单块完成，减少循环与跨块状态更新，但超长输入保留原分块路径，避免无界寄存器扩张。

3. **小输入合并多行并缩窄流式状态。** 属于最终组合，未单独分摊收益。

   ```diff
   - row = tl.program_id(0)
   - cols = tl.arange(0, WIDTH)
   + pid = tl.program_id(0)
   + if pid % 8 == 0:
   +     rows = pid + tl.arange(0, 8)
   +     cols = tl.arange(0, WIDTH)
   +     # 二维加载8行，并沿列轴分别归约；保留行/列边界mask
   +     maximum = tl.max(x, axis=1)
   ```

   同一CTA处理多行可以改善短行的有效线程工作量；原grid中非活动CTA退出，避免重复写输出。单行小输入采用32-lane分片累加，在合法范围内将地址中间量缩为i32，尝试降低宽状态和地址运算成本。

4. **组合上述改动。** 完整30点累计1.1221×。

   ```diff
   - # 所有N使用原启发式对应的计算路径
   + # 运行时范围分派：小输入批处理/32-lane流，长行单块，超长保留原分块
   + if N <= one_tile_limit:
   +     one_tile_path(...)
   + else:
   +     original_online_path(...)
   ```

   收益来自计算量、逻辑tile、状态更新与地址表达的组合，不是某一项寄存器或缓存指标的独立贡献。仍保留持平与回退shape；不同子集下的方法不能逐项相加为整体加速。

51点数值/边界、编译链及memcheck/racecheck通过；限定已映射连续FP16、有限值/-inf、无别名，不覆盖NaN/+inf、任意stride、其他dtype或完整API。
