# Logsumexp：Triton源码与直接TTIR优化的对照实验

本实验把已验收的 `r4_focus` 优化方法回写为公开 Triton Python，和该不可变 TTIR 文件直接配对。下表中的 TTIR/源码 大于1表示源码版更快；不使用两个历史平均值相除推算差异。

**实测结论：这些优化可以回写为公开Triton源码，并复现几乎相同的整体性能。**
TTIR/源码直接配对几何平均为0.99941× / 0.99889×，即源码整体耗时约高0.06% / 0.11%。
主测区间包含1，复测区间略低于1；不能把这种很小的整体差异概括为TTIR独有加速能力。
个别尺寸存在可复测的约1%～3%差异，且有的源码更快、有的TTIR更快。
对照固定为已验收的r4_focus，没有混入尚未验收的快速对数候选。

baseline（原始对照实现）来自用户指定 FlagGems logsumexp.py。性能矩阵、原启发式分组、完整编译选项、设备参数签名和主机grid保持不变。同一H100物理GPU、官方Triton3.7.0、FP16连续输入输出；
原始数值容差不变。

29个组中有16组ELF代码段逐字节一致，覆盖12/30个性能点。完整cubin包含函数名和调试信息，不能把代码段一致说成整个cubin一致。

## 如何表达这些优化

按N分支缩小tile；在线统计量用q=exp(-abs(x-m))和tl.where；大行FP16最大值用自定义tl.reduce后转FP32，因为tl.max会自动提升；长行用65536宽tile与运行时回退；小输入用8行合并、32lane分组；
非内层索引保持i32。全部用公开tl API，没有内联汇编、内部IR builder或二进制替换。

常规源码多经过make_ttir前端优化，直接TTIR文件从make_ttgir开始。源码自己的TTIR文件重编译与原生源码编译的LLVM/PTX/cubin字节一致，TTGIR经相同parser归一化一致。原始源码/基线（原始对照实现）同样逐点核对；

没有跨编译路线混比。

## 验证与计时边界

两个种子分别1224项精度检查通过，覆盖51个shape、8种分布和3个版本；主测源码/TTIR输出逐位一致为408/408个输入组合，复测也为408/408。
两者均按FP64舍入参考及nativeFP32参考检查rtol=1e-3/atol=2e-3。
每次重置输出sentinel（用于发现漏写的预填哨兵值），检查边界与输入未变；memcheck/racecheck各306项通过。

主测7轮、独立进程不同种子复测5轮，每次rep=20ms，随机配对顺序，全部30个A/A对照通过。计时是预分配输出的CUDA graph设备时间，不含CPU提交、分配、编译、模块加载；无清缓存，未主动锁频、锁频配置未知。
全部原始replay样本、执行顺序、运行中遥测、编译产物和内容哈希（用于确认文件是否改变的校验值）保留。

ASTSource原生启动器保留constexpr占位参数，IRSource启动器只接受运行时参数。公共适配包装按各自正确接口传参，实际设备ABI/grid/stream一致。早期适配错误在精度/编译准备阶段被发现并修复，未进入计时；
原日志与失败分类保留。

结论仅覆盖此固定版本和输入矩阵；不外推其他布局/dtype/NaN/+inf、未映射shape或完整FlagGems API。两组机器指令不同也不自动证明显著性能差异，需结合直接配对、A/A波动和复测。
已经观察过的shape属于回归测试集（检查已有输入的行为是否改变），
不是独立新shape测试集。
