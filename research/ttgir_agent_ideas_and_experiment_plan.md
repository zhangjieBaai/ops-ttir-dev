# TTGIR 优化 Agent：两个研究方向与实验计划

2026-11-24 更新。已在 8 张 H100 上完成 4 个开发族、24 个 shape 的可行性实验，含 Triton 3.7.0 / 3.9.0 版本内对照、两卡独立复测和 NVIDIA 官方库基线。下文仍保留原预注册目标和停止线。正式 Agent 对照、盲测与跨族规则迁移尚未启动。文献和结构核查、开发点实测、待验证假设按各自证据范围解读。[可行性总报告与原始数据入口](../../ops-ttgir-dev/pilot_20261124/report.md)

**表达能力的实验证据。** 在 3.7 LayerNorm 的 LLIR 上给 126 条 X 读和 42 条 Y 写定向附加 LLVM 别名域，验证器回读全部 168 处。在已核查的公开源码访存 API 中没有这样的逐指令 metadata 入口；同后缀产生的 cubin 与强基线逐字节相同。[逐指令探针与 cuDNN 对照](../../ops-ttgir-dev/pilot_20261124/alias_scope/report.md)

给 LayerNorm 的 10 个既有运行时分支写入 LLVM 方言的 `expect`，P0 可以通过 verifier，两版 lowering 都生成指定方向的分支权重。普通 tl 源码通过 `core.extern_elementwise` 调用 LLVM expect intrinsic，也实际获得 10 条带权重的分支，并通过数值检查。在两张卡上，改写相对原实现的六点几何速度比均约 1.000；cuDNN 训练态 LayerNorm 在六点几何均值上更快。另测的 CTA 驻留约束可由普通 Triton 的公开编译选项复现，转置布局效果可由 Gluon 或改变数据表示的普通 tl 复现。[分支权重](../../ops-ttgir-dev/pilot_20261124/branch_hint/report.md) · [寄存器和公开编译选项](../../ops-ttgir-dev/pilot_20261124/launch_bounds/report.md) · [转置的源码及 NPP 对照](../../ops-ttgir-dev/pilot_20261124/transpose/report.md)

**阶段决策。** 找到了高于噪声的静态错排，以及一部分跨两个版本可复现的布局敏感性。多消费者 RMSNorm 的候选全部未过收益门槛，INT4 局部赢家随版本改变，LayerNorm 和转置的收益各有其他解释。暂缓启动大预算 Agent 或 B 的迁移实验。[四族判断与 CUDA 基线](../../ops-ttgir-dev/pilot_20261124/report.md)

**第二轮更新。** 在LLVM O3之前标记同一批168条访存，原生ScopedNoAliasAA确实将全部5,292对X/Y访问判为NoModRef；最终cubin与基线相同，两卡stock/early约1.000。将可确认的全局读改为native load后附加invariant/alias信息、以及对INT4生成循环添加五种展开提示，也未改变执行代码。新增六点的blocked写sector模型在两卡36个观测上准确，但选择始终等于baseline，且漏掉短行约5%的收益。当前保留早期干预工具和已验证的流量预测组件，尚无IR标注的独立设备加速。[第二轮总报告](../../ops-ttgir-dev/round2_20261124/report.md)

**第三轮更新（2026-11-25）。** LayerNorm 给出了可定位的跨分支效应。只改动态循环内 5 个读，cubin 与基线相同；只改循环外 205 个读，就还原了全量改写的 cubin。六个静态点实际全局读少 20%，但强基线/候选仅 0.7266 / 0.7219。五个长行点读流量计数相同，IR 得 1.0451 / 1.0437 倍；普通 Triton 只在静态分支显式保留 FP16 tile，长行也得 1.0530 / 1.0530 倍。INT4 交错解码的最佳点约快 2.4%，普通 Triton 在该点生成相同的执行指令。新增九个布局点的预选规则为 1.0279 / 1.0278 倍，低于冻结的 1.03 倍门槛。当前证据支持评估整核编译对候选排序的影响，尚未验证 IR 独占的性能优势。[第三轮总报告与 NVIDIA 库对照](../../ops-ttgir-dev/round3_20261125/report.md)

**第四轮更新（2026-11-25）。** 按普通 Triton、Gluon、前端内联 PTX 分层实测。TTGIR 为行直方图跨 tile 保留 shared 计数器，比已测最快的普通 tl.histogram 源码快 3.893 / 3.903 倍；双方都调优时，手写内联 PTX 可以追平。对每次调用从 CPU 接收新 256B 表的图像查找，聚合按值参数与 CTA 内暂存的组合比最快纯 tl 对照在设备上快 1.1049 / 1.1084 倍，实际提交快 1.0530 / 1.0616 倍；手写标量形参与内联 shared 初始化能取得更低耗时。INT4 流水排空、行排序内部通信也有超过原实现的增量；这轮未验证出在冻结矩阵上稳定超过最强含内联 PTX 源码的独立 3% 收益。[第四轮总报告、源码层级与 CUDA 库基线](../../ops-ttgir-dev/round4_20261125/report.md)

## 1. 选择与研究问题

主推 A，**用实际 lowering 纠正多消费者 TTGIR 区域中布局、转换与重计算的候选排序**。
先检验确定性搜索在强编译器基线上还遗漏哪些有用方案，再测量模型选择下一次试验的增量。
B 保留为 A 的后续迁移实验，聚焦于同一合法改写在未见算子上的收益条件。

两个研究方向如下：

| 方向 | 核心问题 | 最小产物 | 主要风险 |
|---|---|---|---|
| A：区域联合布局搜索 | 哪些候选在静态估价与实际计时中排序相反？后端反馈能否用更少试验找到赢家？ | 区域改写器、静态排序器、带反馈的选择器 | stock pass 或静态排序已足够 |
| B：规则的收益适用条件 | 同一合法规则何时加速、何时回退？部署前能否识别？ | 确定性规则、合法前提、性能反例、未见族评测 | 简单检索已足够，或条件几乎拒绝所有匹配 |

建议先做 A 的可行性探针；A 有真实案例后再做 B。
这里的 Agent 指一个模型驱动的工具调用循环，不要求多 Agent 编排。

### 2.3 可保留的贡献与停止线

**A 的候选论文主张（D 级）。** 我们研究强基线完成布局优化后仍保留的多消费者冲突。针对同一个 SSA 值，一侧消费者可以接收转换后的值，也可以在自己的布局中重算少量纯表达式。两种做法可能交换通信次数、存活区间与写回效率。我们的新增设计是在同一合法计划集合中，先用确定性布局成本模型排序，再用少量已测候选的实际通信路径、资源变化和时间修订其余候选的优先级。固定算法、tile、launch 和编译后缀后，可逐例定位哪些错排来自转换、哪些来自整段代码的相互作用，并量出纠正错排的编译和测量成本。若普通静态排序已能选到相同计划，或者产物反馈不及只看时间，删去相应的反馈主张；只有模型优于同预算非 LLM 决策器时才主张 Agent 的增量。

**B 的判定。** 停止用“从成功与反例归纳 guarded rewrite 并零调用迁移”作为独立 novelty。值得保留的是 A 的下游问题（D 级）：能否用开发族中**同一合法规则**的加速与回退实例，学到一个部署前可判定的收益条件？例如同一种边界移动在一个上下文避免跨 warp 搬运，在另一上下文增加重复计算或把写回变得更贵。若仅从原图及冻结环境就能在未见算子族识别这种差异，系统可省去每个新 kernel 的在线试调。若手写条件、按历史平均收益选规则、简单的特征模型或近邻检索能达到同样的覆盖与回退率，就交付 recipe 和适用范围，不再单列规则学习贡献。判据与盲测方法见第 13 节。

### 2.4 从仓库里能直接核对的起点

- **第一个开发探针用 residual RMSNorm + INT8。** 在归档的 `m128_n4096_w8` 优化输入产物中，`%z = x + residual` 的两个使用分支给归约准备输入，另一路将同一 FP32 值以 `sizePerThread=16 → 4` 转换后写回。对应源码位置的 PTX 在全局写回前有 `st.shared.v4.b32`、`bar.sync` 和 `ldmatrix`。可在保持地址、mask、cast 顺序和原始 load 次数的条件下比较原写回、让输出地址支路采用生产者布局，以及在输出布局中复制纯表达式的合法方案。只有转换消除后全 kernel 独立配对计时仍改善，才有性能证据。这个图已被查看，作为开发实例。[归档 TTGIR，第 47–61 行](../norm_quant/artifacts/ablation_v1/m128_n4096_w8/kernel/final/kernel.ttgir) · [对应 PTX，第 251–297 行](../norm_quant/artifacts/ablation_v1/m128_n4096_w8/kernel/final/kernel.ptx)
- **负对照用 INT4 GEMM 的一个 epilogue。** 在归档的 `m16_n4096_k4096` 产物中，累加结果已经先从 FP32 截成 FP16，再从 MMA 转到 blocked 并写回。对这一处，“先缩位再转换”没有剩余动作。枚举器应返回已满足或跳过，不能故意调换顺序制造收益。这两项是 C 级结构核查，历史 TTIR 加速比不计入 A 或 B。[归档 TTGIR，第 219–221 行](../int4_gemm/ablation/artifacts/m16_n4096_k4096/final/kernel.ttgir)

## 3. A 的具体机制与可证伪假设

考虑一个值同时流向归约和输出两条支路：

```text
                    -> reduction consumer, preferred layout LR
producer value v ---+
                    -> elementwise -> store, preferred layout LS
```

待搜索的选择包括：让公共生产区域采用 LR、LS 或第三种合法布局；在何处分叉；
把转换移到较窄/较低位宽的位置；在不同布局中重算一小段无副作用表达式。
这些选择可能改善通信，也可能增加寄存器、复制或损害合并访存。
联合改动有可能需要经过单步不增益的中间状态，因此候选以一组原子改写提交，不能只保留单步赢家。
本例只是动机，具体任务上是否有这种结构、是否带来收益都需要测量。

| 假设 | 实验比较 | 证伪/收缩条件 |
|---|---|---|
| H1：区域联合决策有 stock pass 未捕获的收益 | stock vs 单点搜索 vs 联合搜索 | 未发现独立复测收益，或收益全来自普通配置变化 |
| H2：lowering 反馈优于只看 IR 或时间 | 同一选择器与静态先验，仅时间 vs 时间加阶段产物反馈 | 等成本曲线无优势，或全部优势由额外测量预算解释 |
| H3：Agent 能比传统策略更有效地选择动作 | 同动作空间随机、局部、静态排序、使用同一反馈的非 LLM 策略与 Agent | Agent 在预算与跨 seed 指标上无优势 |
| H4：结构化动作优于直接生成 IR 文本 | 同模型、同输入、结构化动作 vs raw TTGIR 编辑 | raw 编辑同样稳定有效，结构化接口无成本优势 |
| H5：方法能迁移 | 未见 shape、未参与方法开发的算子族 | 收益仅存在于开发样例；诚实报告适用范围 |

H1 成立而 H3 不成立时，贡献可能是布局搜索器/成本模型，而不是 Agent 优越性。

## 4. 实验契约与编译截点

本文件是新 TTGIR 研究协议，不修改旧 TTIR 实验合同或其结果。
用户已明确讨论转向 TTGIR/LLIR；旧协议“只改 TTIR”适用于旧实验，不能套用为本研究的层级限制。
继承其环境隔离、冻结、同后端、正确性先于性能和完整证据要求。

### 4.1 两条轨道

- **主轨：固定算法与启动配置的 TTGIR 优化。** 不改逻辑 tile、tensor shape、grid、kernel 数、workspace、
  dtype、数学近似、全局访存语义或编译 options。允许合法布局调整和受限纯表达式重计算。
- **扩展轨：与源码/config 搜索组合。** 单独研究 `source -> best source/config -> TTGIR` 的额外收益；
  各段时间与预算分别记录，不能把配置收益归到 TTGIR。

第一版不改异步协议、不删 barrier、不改 MMA 指令类型，不使用 inline PTX。
改变归约输入布局可能改变浮点归约顺序，须按冻结容差验收，并单独区分严格数值轨与允许归约重排轨。

### 4.2 截点与后缀 pipeline

首版使用 stock `make_ttgir` 输出的 TTGIR 为冻结截点 P0。
在本地 Triton 3.7.0，`triton.compile('x.ttgir')` 从 `make_llir` 继续，
不重跑 `make_ttgir`，`ttg.num-warps/num-ctas` 等属性必须和实际 options 对齐。

每个分组先验证：

1. 源码完整编译，保存全部阶段、options、metadata 和工具哈希。
2. 原样导出 P0，按 TTGIR 文件入口重新编译。
3. 比较 LLIR/PTX/ELF `.text` 与输出。完整字节差异必须逐项解释，不能泛称“都是 debug”。
4. P0 的不动点改写经同一 parser/printer 和清理流程，验证无意外语义/机器码变化。

若后端需要的 metadata 不能从文件入口重建，则该组暂不纳入主实验，先实现经过对照的同后缀适配器。
有 tensor descriptor、复杂异步协议或额外 scratch 的组必须单独验证，不能套用普通 kernel 的 metadata。
每个候选由实际后端重新计算 shared/scratch 等资源并经原生 CompiledKernel 启动，不手工套用 baseline binary。

P0 若无法覆盖关键布局选择，再新增 P1：位于最后一次布局消除前的固定 pass 边界。
P1 只作为单独分层实验：baseline 与候选都使用同一个固定前缀、后缀、hook 和工具链，
no-op hook 必须还原 stock 产物。明确记录未重跑/已重跑的 passes。
主论文不能给 Agent 任意选择截点、再与完整 stock pipeline 混比。
定制 hook 是本研究显式允许的实验装置，不混入原 TTIR 主测；环境及 hook 源码单独归档。

## 5. Agent 与改写器

### 5.1 输入与动作

模型输入：算子契约、当前区域的 SSA/use-def 图、布局与转换、允许动作、历史失败摘要，
以及已获准采集的编译资源/产物差异。性能反馈只有搜索集，不暴露最终盲测数据。

模型输出结构化计划，例如：

```json
{
  "region_id": "r7",
  "hypothesis": "将分支边界移到窄值处可能减少转换代价",
  "actions": [
    {"op": "set_region_layout", "region": "r7", "layout_id": "L3"},
    {"op": "rematerialize_pure_slice", "slice": "s2", "max_ops": 4}
  ],
  "expected_evidence": ["conversion routing changes", "shared traffic may decrease"],
  "risk": ["register pressure may rise"]
}
```

`layout_id` 只能引用枚举器生成并通过合法性检查的布局，不能让模型凭空构造不合法编码。
上述 JSON 是接口设计，不是已可运行工具。

### 5.2 首版三个动作

1. **区域布局替换与传播。** 一致更新区域内类型、常量、broadcast/slice/reshape 关系；
   保留区域外接口，在边界插入语义保持的转换。最多 12 个操作的纯 DAG，循环和条件区域先作为边界。
2. **转换边界迁移。** 仅通过已实现合法性规则的 elementwise/broadcast/cast 等操作。
   保持原 cast 舍入点及逐元素表达式；不能为了窄化转换擅自把算术移到低精度。
3. **有限纯表达式重计算。** 复制最多 8 个无副作用 op；先允许常量、整数索引和纯 elementwise。
   不复制 load/store/atomic、随机数、异步 op、barrier 或未知副作用操作，不用 volatile 逼迫保留改写。

联合计划每次至多 3 个动作。布局候选来自原布局、相邻消费者布局和有限 blocked/slice 枚举；
记录候选数量与枚举规则，提供给全部结构化搜索基线。
将修改共享别名而影响无关区域的全局文本替换判为非法；不使用正则直接批量改类型。

MLIR C++ pass/重写库负责结构与合法性；模型只负责选区域、动作与参数。
首周确定与官方 wheel 相匹配的编译/扩展方案；若必须源码构建，则固定官方 tag/commit，
重新建立全部 baseline，并把 wheel 与源码构建结果分开报告。

### 5.3 搜索与反馈

```text
contract + TTGIR graph
    -> select region and joint plan
    -> deterministic rewrite + verifier
    -> compile using fixed suffix
    -> correctness screening
    -> artifact diff + machine-code dedup
    -> paired timing
    -> update history, retain beam, propose next plan
```

beam 宽度 4，同时保留一个非贪心探索槽；单步无收益不能自动否决未完成的联合计划。
后续候选最多 3 层深，所有基线允许同样的深度和联合动作，不能只让 Agent 跨越局部低谷。

反馈区分：非法/不支持、lowering 后消失、相同机器码、不同代码但无计时收益、资源回退、
正确性失败、计时噪声、独立复测收益。`convert_layout` 数量只作线索，不能用它代替成本或收益。
优先从 layout 映射分类转换可能是线程内、warp 内或跨 warp 通信，再用下游产物核对；
分类器不确定时返回 unknown，不能从一条 convert 推断一定有 shared/barrier。

机器码去重键至少含目标、完整 ELF `.text`、常量/全局数据及其引用、launch metadata/ABI。
仅 `.text` 相同不足以断定程序相同。首次重复仍做输出核对；去重开启与关闭作为消融。
不以 register/shared 更少为硬性筛除条件，只有真实测量决定性能。

**一次反馈怎样改变下一步。** 先按第 7 节 B8 的静态分数给合法计划排序。从分数靠前或分数接近但预计通信路径不同的计划中取样，通过正确性筛查后记录实际通信路径、资源变化及配对时间。例如，静态分相近的两个候选分别生成 warp shuffle 与 shared 往返，且计时分化，下一批就可探测其他具有相似源/目标布局的转换，看这个差异能否跨消费者复现。无法关联到区域的 SASS 差异保留为未知。

固定排序之外，设一个确定性反馈对手。以源/目标布局映射、复制的纯 op 和消费者数给计划分组，用已编译记录估计每组实际出现各类通信路径的频率。对已计时的同一批计划计算静态与实测百分位名次差，按实际通信路径取中位数，再用各组的路径频率加权，修正该组未测计划的优先级。没有观测的组沿用静态次序。Agent 得到相同记录与静态先验。更新时间、候选预编译及失败均计入预算，不能免费获得未选方案的机器码。

## 6. 工作负载与数据划分

### 6.1 最小可行性集合

先选 4 个开发族，每族 6 个真实 shape，共 24 点。Residual RMSNorm + quant 和 INT4 dequant + GEMM 包含第 2.4 节已查看的正、负结构线索，LayerNorm 和 transpose + elementwise 用于比较同类归约和二维访存图。6 点从各开发族预划的 search/selection 集取，已查看的归档样例只作开发证据。
每族准备 stock 来源和已有优化来源（有时两者相同）；先导出查看图结构。
若只有一维 blocked 且无实际布局决策，不强行制造冗余转换；保留为负对照，补充真实分支/二维消费者任务。
示范用人为冗余 IR 只验证工具正确性，不能进入性能贡献主表。

### 6.2 完整矩阵

计划 12 个算子族 × 每族 12 点 = 144 点，冻结后不得根据收益删点：

另报告具有至少一个合法动作的 eligible 子集，分母在搜索前冻结。

每族 12 点按实际用途覆盖短/长维、低/高并行度、合法尾部和 dtype，避免只选 2 的幂。

### 6.3 防止把搜索结果当泛化

- 开发族固定包含第 6.1 节的 4 族。其余 8 族在查看结果前按图复杂度分层，用固定种子分给剩余 2 个开发名额、3 个方法验证名额、3 个最终评测名额。只能在前 9 族调整提示、动作与超参数。
- 每族再固定 4 个 search shape、4 个 selection shape、4 个 blind shape。
- 最终评测族允许 Agent 在其 4 个 search shape 上按固定预算在线优化，这是 **在线适配**，不能称 zero-shot。
- 用 selection 集在固定规则下从至多 4 个 beam 候选中选一个可复用 recipe；blind 集只评一次最终 recipe。
- recipe 是按图结构匹配的改写，应用于冻结 shape->IR 映射；不允许事后每点挑最快 IR。
  跨 shape 不能应用时使用 baseline，同时记一次迁移失败。
- zero-shot 规则迁移是 B 的独立实验，禁止目标族任何试运行反馈参与规则选择。
- 最终评测失败后如要修改方法，必须新建版本、明确该批数据已转为开发集，不能继续称盲测。

## 7. 基线：分清“优化有效”和“Agent 有用”

| 编号 | 方法 | 要回答的问题 |
|---|---|---|
| B0 | stock Triton 完整默认 pipeline + 冻结来源配置 | 相对当前编译器是否有收益 |
| B1 | 现有优化 Triton/TTIR 输入的 stock 编译结果 | 是否只修复弱源码基线 |
| B2 | 相同动作空间的随机/均匀采样 | Agent 是否优于简单试错 |
| B3 | 相同动作空间的局部坐标搜索/有限 beam | 联合决策是否超出普通局部搜索 |
| B4 | 相同空间的树结构黑盒优化，如 TPE | 是否只是传统 autotuning 就足够 |
| B5 | 同模型直接编辑 TTGIR，时间与错误反馈 | 结构化接口的作用 |
| B6 | 本方法：结构化联合动作 + lowering 反馈 | 完整方法 |
| B7 | 同模型源码优化，允许 Gluon 的独立组 | IR 接口相对源码接口的实际价值 |
| B8 | 同一合法计划空间上的确定性静态成本搜索 | 简单的目标布局感知估价能否已找到相同收益 |

B8 在小区域对合法计划枚举打分。分数含源/目标线程映射推得的通信类别、搬运字节、重复执行的纯 op 与合并访存代理，权重仅用开发族校准并冻结。按分数取前 k 个进入第 8 节同一编译与计时预算。计划太多时使用预注册的枚举上限和同一候选生成器，记录覆盖率。这是对本文动作集的基线实现，受 Hexcute 和 Tensor Seeks Layout 启发；不把它标成对两篇系统的完整复现。小到可测完的开发区域另作诊断，枚举所得的实测最佳仅作有限集合参照，额外编译/测量单列且不回流盲测。

版本对照另设两组。3.7.0 保留原实验环境；第 2.1 节固定的较新上游版本从**同一源程序与配置**重新生成自己的 P0、stock 和候选，完成各自的 round trip 与同后缀对照。分别报两个版本内的增量。在新版本已消失的机会计为旧版特例。

B2/B3/B4/B8 都可以提交联合动作、收到同样的合法性判定并复用同一测试器。
B0/B1 已包含 stock 布局传播及重计算，不通过关闭 stock pass 构造主要弱基线。
额外做“stock pass 再运行一次/有限重复”的诊断基线，排除只是在做 fixed-point cleanup。
B7 的固定算法组与自由源码/config 组分开；前者尽量保持同一契约，后者报告完整配置预算。
若无法约束源码搜索到同动作空间，明确其属于系统比较，不把差异纯归因于 IR 层级。
既有优化版本逐族核对实际源码/IR 和证据，不推断尚未回写轮次已有源码对照。

## 8. 搜索预算与成本

主预算：每方法、每算子族、每个搜索 seed 最多 32 个候选计划，最多 128 次 case-level 编译尝试，
最多 128 次搜索集 case-level 初筛计时；一个计划在 4 个 search shape 上验证算一个候选，
每个 shape 的编译分别计数。非法、重复、失败计划也消耗候选预算。
缓存命中、复用和超时全部记录，不能把失败成本隐藏到预算外。

默认单次编译超时 120 秒，设备执行超时 10 秒（最终值由开发集校准后冻结）；
单次 run 总 wall-clock 上限 45 分钟，先到任一预算即结束。
每个 Agent run 额外上限 24 次模型调用、100k 总输入 token、24k 总输出 token；记录真实模型版本和费用。
模型最大上下文不足时使用确定性区域摘要，不静默更换模型。
TPE/beam 使用相同区域枚举器，其程序开销也计入 wall time。

最先跑 8、16、32 预算曲线；64 候选只作为预先声明的扩展，不在看到失败后只给本方法加预算。
主结果同时给 equal-candidate 和 equal-wall-time 曲线，不能宣称二者都严格相等。
3 个独立搜索 seed。相同模型用于全部模型方法；模型敏感性只在固定 4 族子集增加第二种模型。

机会探针阶段先跑 stock 和无 LLM 的单点/联合枚举、B8；通过第 12 节的机会探针门槛后，再做含随机、局部、B8 与 Agent 的小规模预算比较（每搜索方法 16 候选、1 seed）。
主环境完整 7 个搜索方法（B2 至 B8）×12 族×3 seeds×32 计划，
约 8,064 个计划上限；每计划多 shape 编译，真实编译数、GPU 小时和模型费用由 pilot 外推。
较新上游版本先复核开发探针，再对预注册的支持族单列验证成本。确定性方法若多次运行给出同一排序，报告一条决策轨迹，多次计时只用于估计噪声。第 11 节各消融在固定子集运行，均在最终评测前冻结。
不预先声称一周或固定费用一定足够。

## 9. 正确性与性能协议

### 9.1 正确性

1. IR verifier、支配关系、布局合法性、类型及副作用检查。
2. 按契约生成随机、全零、常量、极值、归约抵消、尾部掩码、偏移对齐和支持的 stride 用例。
3. 以 CPU FP64/明确的高精度 reference 和原生 ATen 作数值参考；小规模加强 CPU 验证。
4. 每族容差在 baseline 阶段按 dtype/算法冻结，候选不能因误差变大而放宽；记录绝对/相对误差及失败分布。
5. Top-K 等离散输出要求索引/值及 tie/NaN 规则符合契约；同值排序未承诺时使用预定义等价判据。
6. canary、输入不变、支持范围内的别名/非别名检查。明确 NaN/Inf/符号零是否属于支持域。
7. 每个通过初筛的最终候选做 memcheck/racecheck；若工具不支持操作，记录覆盖限制，不能写成全部通过。
8. independent process + 新 seed 复验。测试通过是有限范围证据，不是全域证明。

首次 candidate 与 timing seed 分离；隐藏 correctness 集由测试器持有，模型不能修改 reference 或测试。
测量前所有输入准备和 reference 计算在 host 测试流程完成；kernel wrapper 只分配和启动。

### 9.2 性能

- 只隔离一张空闲 H100 执行同场对照，记录物理 UUID；同设备不并行 benchmark、sanitizer、NCU。
- 每点 baseline/candidate 使用同输入、配置、输出预分配、原生后端和 launcher。
- 主指标为 CUDA graph kernel device time；单独给出普通调用时间，不混合成同一指标。
- 搜索初筛：3 轮，随机交错，rep=10ms；最终测量：7 轮，rep=20ms。
- 独立进程复测：5 轮，rep=20ms，新 seed；统一预热从 500ms 起在 pilot 校准后冻结。
- 采用配对样本速度比，保留所有原始时间、顺序和环境，不能只挑最快值。
- 每会话先做 A/A；预注册门槛为 geomean 偏差≤1%，任一点≤3%。
  失败则整会话弃用并保存原样日志，不能仅删除不利样本。pilot 如需调门槛须在正式搜索前冻结。
- 不宣称冷缓存；若研究 streaming，另建带清缓存成本定义的协议。
- NCU 只分析冻结的赢/输/无变化分层子集，不使用其带 instrumentation 时间替代主计时。
- NCU 反馈在所有算法中限制为同样最多 4 个候选；主方法可主要使用编译产物反馈，避免 profiler 成本主导。

选择规则：selection 集 geomean≥1.02，最差点≥0.98 才部署候选；否则使用 baseline。
此规则在搜索前冻结，阈值是工程目标而非预期结论。blind 结果全部保留，包括越过回退线的点。
blind 发现数值/内存错误后，系统实际产物回退 baseline；同时将该 run 记为正确性失败，
原候选速度不计入有效加速，原始错误不得通过 fallback 隐藏。

## 10. 主要指标与统计

主表回答三件事：收益多少、花了多少成本、能覆盖多少任务。

- 每族等权的 geomean speedup：先对族内 blind shape 的速度比取几何均值，再对族取几何均值。
- 系统全任务结果包含 unsupported、未找到候选和验证失败的 baseline fallback；同时独立列出失败率与 eligible 子集。
- `fast_1.02` / `fast_1.05`：独立正确性合格且 blind 速度比达到对应阈值的任务比例。
- 负回退比例（<0.98）、最差点、逐族完整数据；均值不能遮盖回退。
- 首次找到可复测收益所需的候选数、编译数、wall time、GPU time、token/费用。
- 合法候选率、正确率、不同机器码率、有效增益率、动作被后端消除比例。
- 预算-性能曲线面积与 best-so-far 曲线；时间起点包含分析、LLM、编译、验证与 profiling。
- 零搜索迁移与在线适配分别统计，硬件迁移与普通重测分别统计。

先给每个 seed 的完整结果，再汇总搜索 seed 的分布；测量重复不能充当独立搜索样本。
性能置信区间分别对配对计时和按族聚类的结果估计；12 族/3 seed 的统计能力有限，
明确标注区间仅覆盖已测工作集和条件，不外推所有 kernel。
不要在最终测试集上重选 prompt、recipe 或最有利 seed；不以多次尝试后的最好一轮冒充独立复测。

## 11. 消融与机制实验

在预先按图类型选定的 4 族子集进行下列消融，至少 3 搜索 seed：

| 实验 | 保持相同 | 检验内容 |
|---|---|---|
| 单点动作 vs 联合动作 | 模型、枚举空间、候选预算 | 联合选择是否越过局部低谷 |
| 有/无纯表达式重计算 | 其他动作与反馈 | 重计算是否带来独立价值 |
| 只有时间 vs +IR结构 vs +lowering产物 | 模型和调用上限 | 反馈的增量价值及成本 |
| 有/无机器码去重 | 候选预算 | 是否主要靠避免重复编译/计时 |
| 结构化动作 vs raw IR | 模型及输入材料 | 非法率、修复成本和有效搜索率 |
| 相同图反馈给非LLM策略 | 动作、测量协议 | 收益来自反馈还是模型选择 |
| P0 vs P1（若实现） | 各自匹配baseline/后缀 | 截点是否决定收益，不混为统一样本 |

机制案例选 2 个获益、2 个回退、2 个无变化，公开改写前后 IR、下游机器码及资源。
对于联合候选做 A、B、A+B 的 2×2 对照，确认组合交互；不要把组合总收益分配给单项。
只在原样、单改 X、单改 Y、X+Y 四项各自合法时估计交互。以配对的 log time 计算交互 `log(tXY) - log(tX) - log(tY) + log(t0)`，负值表示联合耗时低于两个单改按乘法推得的耗时。缺失合法单项时报告动作依赖，不计作交互证据。对小区域另外报告静态候选两两错序率（独立复测无法区分的计时对单列）、同预算选中方案距有限集合实测最佳的差距，以及看产物后比仅看时间少花了多少次编译/计时。去重双方都启用时再检验反馈增量；已编译后发现重复只能节省后续处理和计时，当次编译仍计费。
记录 registers、spill、shared bytes、通信指令与相关 NCU 指标；这些用于解释，不代替计时。
静态 barrier 数减少不能直接推断动态执行次数减少，须结合控制流或动态证据。

## 12. 早期门槛、日程与退出路径

按依赖顺序推进，不启动未通过前一门槛的大规模搜索。

| 阶段 | 预计投入 | 交付与门槛 |
|---|---|---|
| P0：工具与证据链 | 第1周 | 4族24点 source/TTGIR round trip、准确性和A/A；确定匹配的MLIR改写构建方案 |
| P1：优化空间探针 | 第2周 | 不用 LLM，做单点/联合枚举与 B8 排序。至少 2 个真实族相对强来源基线有独立复测的 ≥3% 收益；对声称可纠正的错排给出至少一个超过复测噪声的实例，并复核较新上游 |
| P2：Agent最小闭环 | 第3周 | 结构化3动作、有限beam、完整预算；与随机/局部/TPE比成本曲线 |
| P3：完整对照 | 第4--5周 | 冻结方法后运行完整矩阵、3seed、消融、独立复测 |
| P4：迁移与整理 | 第6周起 | 未见shape/算子结果、失败案例、可选第二种架构、复现包 |

日程是工程估算，源码构建和候选吞吐可能使其延长。首版无需训练或微调模型。

退出/收缩条件：

- P0 不能保持同编译后缀或生成可验证合法变换：先完成工具，不启动性能搜索。
- P1 无真实收益，只有人为退化样例改善：暂停 A 的 Agent 开发，重新核查实际图/截点；
  最多新增一次预注册 P1 截点探针，不无限切换截点追正结果。
- 只有一个族获益：收缩为专项算子优化，不能讲普适 Agent。
- 联合搜索有效而 LLM 与 B8、同反馈非 LLM 策略或 TPE 相当：保留可验证的编译搜索贡献，删除 Agent 优势主张。仅在旧版本有效则报告版本特例。静态最优充分解释结果时，收缩为成本模型或编译器补丁。
- 收益来自未对齐的 tile/options 或较弱 baseline：修复基线，旧比较作废。
- 不同代码却无收益：保留负结果，重新评估布局搜索的适用范围与投入。

继续投入的方向性标准：完整方法相对强基线在多个族有独立收益，且在至少一个主要预算指标上优于传统搜索。
期望全任务 geomean≥1.03、至少3族≥1.05可以作为项目管理目标，绝不是论文结果的预告或必须“做出来”的数字。

## 13. B：带适用条件的可复用规则归纳计划

研究问题聚焦在收益条件。对同一条合法规则收集开发族的加速、回退、持平实例，估计哪些源图特征能预测其在未见族上是否值得应用。语义反例用于修订合法前提，性能回退单独进入收益条件归纳，测量落在噪声带的实例保留为不确定。

产物分三层：

1. 语义合法性 guard：类型、布局约束、纯表达式、副作用、别名、控制流前提。
2. 性能适用域：shape/dtype/目标架构/编译截点的经验条件，不能冒充语义正确性证明。
3. 确定性 rewrite 与反例集：失败不覆盖旧规则，用新版本和拒绝原因修订。

首版只归纳既有3动作的匹配模式、参数与guard，不允许任意生成未经审计的编译器代码。
若进一步生成PDL/C++ pass，必须作为后续轨道增加静态检查和针对性合法性测试。

数据：来自开发族成功与反例的20--50组候选，只有真正存在这些案例才启动；不得先假定样本量足够。
测试分为同族新shape、异族zero-shot、第二硬件/新编译器版本；后两者分开，版本变化不得混用旧metadata。
部署时只读原图中的 use 数、类型/位宽、源与候选布局的静态映射、shape、目标及编译器版本。可从相邻用途推导通信类别。开发阶段可以用候选 SASS/资源差异和配对时间作标签；部署时读取未选候选的机器码会引入候选编译成本。主 zero-shot 组每个命中只确定一个改写，不为选规则试编或计时，不调用模型；允许编译所选产物并做独立正确性验收，单列部署成本。

收益条件的一个可执行做法是从同一规则、相近 shape/dtype 而配对收益异号的开发实例开始。例如两个实例只在消费者数和目标布局的跨 warp 映射上不同，就测试这两个静态谓词能否把回退实例排除，同时保留其他开发族的赢家。枚举少量谓词的合取或析取，在开发族留一验证上按族等权评估含回退到 stock 的总收益与覆盖率，保留达到预定覆盖、可复现且最短的条件。候选谓词、复杂度上限与选择标准在测试前冻结。多个特征随同一谓词共同变化时，只把它当作预测条件，归因另做受控改写。

对照使用相同审计动作与合法性前提。依次比较全收合法匹配、手写收益条件、最近邻 recipe、按发现阶段平均收益排序（RuleFlow 式）、相同源特征与样本训练的浅决策树，以及上述利用同规则正反例的条件归纳。在均未见目标族反馈时比覆盖率相当处的回退率与全任务速度比；在线 Agent 另报成本。安全性检查在各组始终开启。
匹配所有规则时的选择逻辑冻结，不用目标测试集时间挑最快规则。
指标：分别给出结构匹配数、合法数、决定应用数和独立复测加速数，报告有效收益精度、回退率、零搜索全任务速度比及部署开销。为估计误拒，冻结全部选择后，在独立评估器离线复测事先分层抽取的拒绝实例，按抽样概率估计漏掉的收益并标出不确定性。复测费用计入评估，不回流规则选择。另报规则复杂度与维护成本。
形式验证仅能覆盖所支持的局部子语言；其余结论明确标为测试证据。

门槛：至少 3 条规则能在独立算子族复现收益。在预先冻结、有足够匹配样本和覆盖率的比较点上，相比上述简单方法能减少性能回退且保留收益，并能给出同规则在不同上下文实测变号的正反例。仅语义匹配次数增加或样本过少，均不足以证明收益条件可迁移。
如果规则只能复现单算子shape特化，收缩成recipe库，不宣称跨算子优化知识。
预计在A积累证据后追加2--4周；无需与A同步展开。
