# Attention 反向 dK／dV TTIR 优化

来源：官方 Triton v3.7.0 融合 Attention 教程的反向 dK/dV 计算部分。基线每个 CTA 负责 128 个 key；LSE、delta 和预缩放 K 已提前准备，计时只包含 dK/dV kernel。

环境：官方Triton3.7.0，H100，SM固定1200MHz，FP16输入、FP32 dot累加，4 warps / 5 stages / 1 CTA。D64/128、因果/非因果共32点。预分配CUDA graph设备计时，不含分配、编译或CPU launch，配对计时与A/A检查通过。

**最终平均加速比：算术平均2.023846×，几何平均1.800224×。** 覆盖全部32个shape，A级性能证据。

优化方法与性能提升：

1. **dV的cast/dot后移到dK之后（D64最终版）（D64全部16点）。** 增量1.126552×、累计1.126552×。

   ```diff
   - ppT = pT.to(tl.float16)
   - dv += tl.dot(ppT, do)
     dpT = tl.dot(v, tl.trans(do)).to(tl.float32)
     dsT = pT * (dpT - Di[None, :])
     dk += tl.dot(dsT.to(tl.float16), tl.trans(qT))
   + ppT = pT.to(tl.float16)
   + dv += tl.dot(ppT, do)
   ```

   延后概率的FP16副本及dV消费位置，调整dK/dV两条dot路径同时活跃的中间值和调度机会。两个梯度accumulator各自的累加顺序不变，收益来自整个编译结果；这里只对D64的16点成立，不能外推D128。

2. **每CTA串行处理两个64-key子块（D128非因果8点）。** 增量2.707942×、累计2.707942×。

   ```diff
   - # 一个CTA持有[128,D]的dK/dV状态
   - key_rows = start_key + tl.arange(0, 128)
   + for sub in range(2):
   +     key_rows = start_key + sub * 64 + tl.arange(0, 64)
   +     # 每次只计算、写出一个[64,D]子块
   ```

   将同一CTA的输出状态拆成两个64-key子块，缩小dK/dV累加器与中间概率块，缓解宽矩阵带来的寄存器/spill压力。原CTA数和输出归属不变，但Q/dO可能读取更多次，不能描述为免费减半计算量。

3. **再依据query坐标重算指针（D128非因果8点）。** 增量1.054566×、累计2.853300×。

   ```diff
   - q_ptrs += QUERY_BLOCK * stride_q
   - do_ptrs += QUERY_BLOCK * stride_do
   + q_ptrs = Q + base_q + query_rows[None, :] * stride_q
   + do_ptrs = DO + base_do + query_rows[:, None] * stride_do
   ```

   非因果组按当前query坐标重算指针，减少循环携带的地址状态，为后端布局和寄存器复用提供不同表达。重算本身增加部分整数运算，收益不能简单解释成地址指令更少，须由编译后的资源和完整kernel耗时确认。

4. **再后移dV（该组最终版）（D128非因果8点）。** 增量1.052222×、累计3.005164×。

   ```diff
   - ppT = pT.to(tl.float16)
   - dv += tl.dot(ppT, do)
     dk += tl.dot(dsT.to(tl.float16), tl.trans(qT))
   + ppT = pT.to(tl.float16)
   + dv += tl.dot(ppT, do)
   ```

   在64-key及指针重算已经存在的上下文中再后移dV，进一步调整两个dot路径的活跃中间值。这是D128非因果组的条件效应，不能与D64的收益相加或作为所有尺寸的统一收益。

5. **每CTA串行处理两个64-key子块（D128因果8点）。** 增量2.376310×、累计2.376310×。

   ```diff
   - key_rows = start_key + tl.arange(0, 128)
   + for sub in range(2):
   +     key_rows = start_key + sub * 64 + tl.arange(0, 64)
   +     # 保留因果mask，依次计算两个64-key子块
   ```

   因果组也缩窄输出累加状态，但必须保留query遍历和因果mask边界。减少同时活跃状态可能降低spill代价，同时仍付出重复读取Q/dO的成本，不能直接套用非因果组的加速比。

6. **再静态展开两个子块（D128因果8点）。** 增量1.110712×、累计2.639140×。

   ```diff
   - for sub in range(2):
   + for sub in tl.static_range(2):
         # 按sub计算子块偏移及因果遍历范围
   ```

   固定两个子块的偏移和边界在展开后对编译器可见，有机会简化控制与地址依赖并重新调度加载/dot。代码体积和活跃值也可能增加，实际效果是当前因果组的受控对照结果，不是静态展开总会加速。

7. **再后移dV（该组最终版）（D128因果8点）。** 增量1.043301×、累计2.753818×。

   ```diff
   - ppT = pT.to(tl.float16)
   - dv += tl.dot(ppT, do)
     dk += tl.dot(dsT.to(tl.float16), tl.trans(qT))
   + ppT = pT.to(tl.float16)
   + dv += tl.dot(ppT, do)
   ```

   在因果组的64-key与静态展开结构上再次调整dV消费顺序，保持各accumulator的数学累加顺序。64-key、展开和dV后移有交互，累计数字只针对标注的8点；全32点平均仍由前表单独计算。


条件收益不能相加。增量相对前一版本，累计相对原始基线，各项存在依赖和交互。

方法表各行明确标注适用子集；其累计加速是该子集相对原baseline，不能当作全32点收益。下表及最终算术/几何均值均覆盖全部32点。64-key与结构调整存在依赖，联合移除不冒充纯单项贡献。当前dK/dV保持基线逐位一致，另有小N CPU FP64数学参考；不含forward、K预缩放、delta准备或完整backward。

全部时间、加速比和方法收益使用同一组原始配对样本；冻结最终选择不变。新增中间消融未全部重跑sanitizer，最终版沿用已有通过记录。
