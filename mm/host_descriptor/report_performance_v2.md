# Host descriptor v2：用户允许同步告警后的性能结果

**本组六点的 CUDA graph 设备时间有收益。**
最终选择 host-TMA 加 PID 映射版本，主测几何平均加速比 **1.1247×**，独立进程复测 **1.1171×**。
这里的比较用原始版本称为基线（baseline）。基线与候选使用相同的新 host 参数接口。

**racecheck 告警没有解决，也没有被改标为通过。**
用户明确指示“告警可以忽略”，本 v2 按这个例外继续优化。
结果只代表该授权下的数值与性能选择，不授予同步正确性或生产安全资格。
旧固定接口的 `optimized.ttir`、六组映射和旧选择没有被覆盖。

## 改了什么，哪些保持不变

host-TMA 版本由自己的 TTIR 直接改写，使用 host descriptor 参数和 descriptor load/store。
第二个候选只把组内行号从`(pid % width) % size`改为`pid % size`。
它可改变尾组行的排列，但仍覆盖相同输出 tile 集合；非初始三行尾组有数值用例覆盖。
浮点 dot 的顺序、分块和启动配置保持不变。

新接口的基线保留教程计算和普通指针加载，加入相同的 descriptor 加指针参数。
双方为12个逻辑参数，原生展开为24个物理参数，scratch均为0。
它们通过同一个局部签名适配、原生编译和原生 launcher 执行，各自使用真实描述符元数据。
没有修改安装文件、编译阶段或编译后 GPU 产物，也没有给基线加入虚假 GPU 工作。

图中计时使用同一输入和预分配输出，描述符对象也提前准备。
计时包含所有必要 GPU load、dot 和 store，排除 JIT、加载、CPU 编码和内存分配。
因此它是**新接口下的设备时间收益，不是原指针 Python 接口的端到端收益**。
全部尺寸已暴露，不称新的独立保留集；未锁频、无主动缓存清理或持续独占保证。
其他五个 MM 配置组没有本轮新性能结论。

## CPU 与实际调用成本

仅创建三个 TensorDescriptor 对象，主测中位数约7.3–7.4µs，复测约7.5–7.7µs。
这不含原生 tensor-map 编码；编码包含在下面的实际调用时间中。
每点10轮随机调用顺序，测调用前后同步之间的 CPU wall time。
“调用”包含描述符准备、编码、启动和完成同步；“含分配”另外包含输出 `torch.empty`。

| 边长 | 描述符对象准备 µs | 匹配基线调用 µs | 选中版本调用 µs | 原指针调用 µs | 选中版本含分配 µs | 原指针含分配 µs |
|---:|---:|---:|---:|---:|---:|---:|
| 768 | 7.32 | 52.09 | 51.71 | 40.88 | 59.89 | 48.35 |
| 896 | 7.41 | 52.21 | 51.06 | 40.57 | 60.08 | 48.10 |
| 1024 | 7.35 | 51.18 | 51.01 | 40.31 | 61.01 | 48.52 |
| 1152 | 7.39 | 55.82 | 55.45 | 44.91 | 63.06 | 52.28 |
| 1280 | 7.33 | 55.93 | 54.86 | 45.22 | 63.21 | 52.95 |
| 1408 | 7.34 | 58.14 | 56.52 | 47.02 | 65.43 | 54.64 |

这是主测进程的逐点中位数；复测所有原始样本也已保存。
共享新接口的基线与选中版本调用耗时接近，而原指针接口明显更短。
因此**没有得到原指针接口包含准备成本后的调用加速**。
这些小样本 wall time 受 Python 与同步开销影响，不等同于应用吞吐或完整应用端到端指标。
新增公开入口还有选择和输入检查，不能把测试包装的精确 wall time 直接标成该 API 的实测调用时间。

## 正确性、告警与实际入口

主测及 seed123 复测分别对三个版本各查37项，覆盖六个性能点和扩展边界/压力输入。
新增 PID 候选的 memcheck、racecheck 各再查37项；共296次数值用例通过，包含重复用例。
对照是 native FP16、禁 TF32 的 FP32，以及小尺寸 CPU FP64，容差为atol=.01、rtol=.001。
有限性、输出未写入标记、行尾保护区和输入不变检查均保留。

- memcheck：0 errors。
- 新 PID 候选 racecheck：37条 warning，退出99，未解决。
- 原 host 版的37条 warning 及其同步定位保持原样，没有删除或关闭检测。

[selection.json](results/performance_v2/selection.json) 明确记录用户例外和`sync_qualified=false`。
选择文件按当前源、编译产物、完整六点覆盖及原始配对样本核查，不放宽数值或计时门槛。
`ir/selected_host.ttir`是选中`host_pid_v2.ttir`的字节副本，没有替换旧 MM 文件。

新入口 [api.py](api.py) 提供`load`、`prepare`、`run_prepared`和`matmul`。
全部六点的分配/预准备调用、一次 graph replay、未知尺寸拒绝均检查通过。
选中别名与源文件的原生 cubin 字节一致。输入、输出及描述符在使用期间必须保持地址和布局不变。
这个入口携带未解决告警，不应被称为已通过同步资格验证的生产优化。
