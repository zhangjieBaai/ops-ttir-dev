# MM TTIR 优化

来源：官方Triton v3.7.0矩阵乘教程，逐shape autotune后冻结六组配置。改用host descriptor/TMA，匹配基线使用普通指针load/store但保留同一新host ABI。

环境：H100，FP16输入输出、FP32累加，GROUP_M=8、1 CTA，tile/warps/stages按冻结配置族。M=N=K=256…4096、步长128，共31点；准备好的descriptor/输出的CUDA graph设备时间，7轮20ms。预分配CUDA graph设备时间，不含分配、编译和CPU launch。

优化方法与性能提升：

1. **以host TMA描述符搬运矩阵块。** 完整31点相对匹配基线的几何加速1.0449×。

   ```diff
   - a = tl.load(A + rows[:, None] * stride_am + ks[None, :] * stride_ak, mask_a, other=0)
   - b = tl.load(B + ks[:, None] * stride_bk + cols[None, :] * stride_bn, mask_b, other=0)
   + a = a_desc.load([pid_m * BM, k0])
   + b = b_desc.load([k0, pid_n * BN])
     acc = tl.dot(a, b, acc)
   - tl.store(C + output_offsets, acc.to(tl.float16), mask_c)
   + c_desc.store([pid_m * BM, pid_n * BN], acc.to(tl.float16))
   ```

   描述符在host提前准备，规则二维块搬运可由TMA相关硬件路径承担，减少逐元素地址和掩码构造，为Tensor Core计算供数。是否形成更好的流水仍取决于后端lowering和同步；当前设备计时不含描述符准备成本。racecheck仍有告警，所以不能把设备时间改善解释为已完成同步资格验收。

2. **简化分组PID到矩阵行块的映射。** 完整31点相对匹配基线的几何加速1.0492×。

   ```diff
   - pid_m = first_pid_m + (pid % num_pid_in_group) % group_size_m
   + pid_m = first_pid_m + pid % group_size_m
   ```

   在原固定分组映射的合法范围内，改写组内行号计算，给编译器简化整数取模及依赖链的机会。收益由整个编译结果决定，未证明某一条取模指令承担全部差异；两候选各自与基线配对，不能用两个整体均值相除作为独立确认的增量。

3. **按完整配置组采用或回退。** 384³…640³采用host TMA，768³…1408³采用host TMA+PID，其余保留基线。

   ```diff
   - # 将同一种TMA候选推广到全部配置组
   + # 按已冻结的配置组选择实现
   + selected = family_selection[family]
   + selected_kernel = kernels[selected]
   ```

   不同矩阵块配置对应不同的寄存器、共享内存与搬运/计算比例，一种优化不必适合所有组。本项是选择策略，不是新的设备指令优化；前表仍保留全部TMA+PID候选的负结果及计时无效标记。

‡表示固定计时修补后仍有控制无效，该表整体为B级研究观测，不能声称全部31点稳定收益。数值和memcheck通过；racecheck仍有72 warnings、0 errors，未获同步资格。不计descriptor准备的端到端成本，最终选择仍按已有配置组决定。
