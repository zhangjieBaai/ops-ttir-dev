# Grouped / biased MoE routing TTIR 优化

来源为 FlagGems Hopper 的 grouped_topk。第一个 kernel 为 8 个连续等长专家组计算带 bias 的最高两分之和，第二个 kernel 选 4 组和 8 个专家，用未加 bias 的 sigmoid 分数生成归一化权重。同分优先小索引，保留原始两次 launch、grid 和中间工作区。[冻结源码及哈希](upstream/provenance.json)

环境为 H100 80 GB、官方 Triton 3.7.0、FP32、4 warps / 3 stages。冻结矩阵覆盖下表 30 个 (tokens, experts)。CUDA graph 对预分配输出计时，含两阶段设备执行；分配、编译及 Python 调度在计时区间外。主测 7 轮、独立进程复测 5 轮，rep=20，随机交错，A/A 均通过。两次均逐 shape 核对源码基线与 TTIR 入口 LLVM、PTX、cubin 一致。[主测](multiround/r6/results/main/performance.json) · [复测](multiround/r6/results/repeat/performance.json)

## 优化方法与平均收益

| 改动 | 测试矩阵 | 相对当轮父版本，主测 / 复测 | 决策 |
|---|---:|---:|---|
| 以组选择向量广播替换专家与组的二维比较和归约 | 8 | 1.1502× / 1.1502× | 接受 |
| 8×8 稳定排名选组、有序 uint32 专家分数、循环结束后 gather 原始权重 | 30 | 1.1859× / 1.1860× | 接受 |
| 展开 8 次专家选择 | 30 | 1.0011× / 1.0009× | 保留父版本 |
| stage 1 双值归约计算组内 top2 | 30 | 1.0186× / 1.0194× | 低于 2% 晋升门槛 |
| 对两阶段固定整数参数做特化，同时加入双值归约 | 30 | 1.0725× / 1.0718× | 接受 |
| stage 1 每个活动 CTA 批量处理 4 组，保持 stage 2 字节相同 | 30 | 1.0234× / 1.0231× | 接受 |

第二轮在同一父版本上单独测有序 key、gather 和稳定排名，初筛几何均值分别为 1.0601×、1.0781×、1.0327×（B级）。第六轮每个活动 CTA 分别处理 2、4、8 组的初筛增量为 1.0171×、1.0240×、1.0181×（B级）。每项增量均取自本轮同场配对，首轮与后续轮次矩阵不同。[首轮](report_round1.md) · [第二轮](round2/report.md) · [第三至五轮](multiround/report.md) · [第六轮](multiround/r6/report.md)

## 新增两阶段交叉消融

从冻结原始基线和最终版各取两个 kernel，测量基线、仅替换 stage 1、仅替换 stage 2、两者都替换四种组合。对每个 E 固定选 M=16、512、8192，覆盖小、中、大 token 数。每项均计完整两次 launch，共用工作区合同，加速比取同场原始基线时间除以组合时间。GPU 5 主测 5 轮，GPU 6 独立种子复测 3 轮，rep=10，以下每格按主测 / 复测排列。六点消融作为 B 级子集证据。

| Shape | 仅替换 stage 1 | 仅替换 stage 2 | 两阶段均替换 |
|---|---:|---:|---:|
| (16, 256) | 1.0461× / 1.0477× | 1.3576× / 1.3542× | 1.4438× / 1.4426× |
| (512, 256) | 1.0681× / 1.0685× | 1.3616× / 1.3624× | 1.4917× / 1.4934× |
| (8192, 256) | 1.0063× / 1.0075× | 1.3783× / 1.3782× | 1.3908× / 1.3924× |
| (16, 512) | 1.0458× / 1.0509× | 1.4042× / 1.4029× | 1.4968× / 1.5032× |
| (512, 512) | 1.1142× / 1.1115× | 1.4510× / 1.4528× | 1.7064× / 1.7012× |
| (8192, 512) | 1.0412× / 1.0421× | 1.6327× / 1.6328× | 1.7451× / 1.7455× |
| **6 点几何平均** | 1.0531× / 1.0542× | 1.4279× / 1.4275× | 1.5402× / 1.5410× |

六个点上，单独替换负责选组、选专家及写权重的 stage 2 都比单独替换计算组分数的 stage 1 收益大。stage 1 的贡献随形状而变，主测单独替换时从 (8192, 256) 的 1.0063× 到 (512, 512) 的 1.1142×。

每次先通过 6 个 shape 的源码与文件编译路径检查，再对 4 个组合 × 6 个 shape × 8 类分布做 192 项检查。group score 与 weight 相对基线逐位相同，index 与 CPU 参考精确一致；另查 CPU 权重容差、canary 和输入完整性。两次消融的 A/A 逐点中位数均落在 [0.97, 1.03]。计时 JSON 包含随机顺序、各轮耗时及编译哈希。[消融主测](stage_ablation/main/performance.json) · [独立复测](stage_ablation/repeat/performance.json) · [主测数值](stage_ablation/main/validation.json) · [复测数值](stage_ablation/repeat/validation.json)

## 复现

在仓库根目录使用空闲 H100 和新的输出目录运行。完整 30 点流程及最终版 memcheck、racecheck 记录见[第六轮复现说明](multiround/r6/README.md)和[验收报告](multiround/r6/report.md)。六点交叉消融命令如下。

```bash
CUDA_VISIBLE_DEVICES=5 OMP_NUM_THREADS=2 /root/venvs/ir-ops-dev/bin/python moe_routing/stage_ablation/run.py moe_routing/stage_ablation/main_new --seed 42 --rounds 5
CUDA_VISIBLE_DEVICES=6 OMP_NUM_THREADS=2 /root/venvs/ir-ops-dev/bin/python moe_routing/stage_ablation/run.py moe_routing/stage_ablation/repeat_new --seed 123 --rounds 3
```
