# Residual RMSNorm＋动态 INT8 TTIR 优化

来源：参考 FlagGems 残差融合 RMSNorm 与动态激活量化数据流建立的融合研究基线，并非生产算子的原样提取。单 kernel 完成残差加法、RMSNorm、amax 和 INT8 量化，输出 FP32 残差 Z、逐行 scale 和 INT8 Q。 参考源码：[残差融合 RMSNorm](https://github.com/flagos-ai/FlagGems/blob/ef8aea78fed8321c3e02a15bf31e847cd0579e4f/src/flag_gems/fused/fused_add_rms_norm.py)、[动态激活量化](https://github.com/flagos-ai/FlagGems/blob/ef8aea78fed8321c3e02a15bf31e847cd0579e4f/src/flag_gems/fused/act_quant.py)（链接固定到实验使用版本）。

环境：官方Triton3.7.0，H100，连续有限FP16 X/R/W、FP32统计和Z/scale、INT8 Q，无别名，N≤16384。每点固定原4/8 warps、3 stages、1 CTA；配置只做过有限预调优。预分配CUDA graph设备计时，不含分配、编译或CPU launch，配对计时与A/A检查通过。

优化方法与性能提升：

1. **利用正rho将amax(abs(rho*u))因式分解。** 增量1.025108×、累计1.025108×。

   ```diff
   - amax = tl.max(tl.abs(u * rho), 0)
   + max_u = tl.max(tl.abs(u), 0)
   + amax = max_u * rho
   ```

   rho为正，amax可因式分解，将向量端乘rho后的max改成先对u归约、最后做一次标量乘法。max不必等待RMS统计和rsqrt结果，解除两项统计的依赖，为后续合并归约创造条件；量化容差保持原合同。

2. **再将sum(z²)/max(abs(u))合为tuple归约。** 增量1.011591×、累计1.037136×。

   ```diff
   - ss = tl.sum(z * z, 0)
   - max_u = tl.max(tl.abs(u), 0)
   + # sum_max按分量合并：sum相加、max取较大值
   + ss, max_u = tl.reduce((z * z, tl.abs(u)), axis=0, combine_fn=sum_max)
   ```

   将两个独立统计放在同一个归约表达式中，有机会共享数据遍历和跨线程归约的调度。tuple也增加携带状态，不能只凭一次tl.reduce就断言barrier或寄存器一定减少；性能以当前组合实测为准。

3. **再给Z/Q/scale输出加.cs。** 增量1.002769×、累计1.040261×。

   ```diff
   - tl.store(Z + offsets, z, mask)
   - tl.store(Q + offsets, q, mask)
   - tl.store(S + row, scale)
   + tl.store(Z + offsets, z, mask, cache_modifier=".cs")
   + tl.store(Q + offsets, q, mask, cache_modifier=".cs")
   + tl.store(S + row, scale, cache_modifier=".cs")
   ```

   给三类输出流式写入提示，尝试降低只写不再读的数据对缓存的挤占。完整矩阵增量约0.28%，不足以单独宣称稳定优化，也没有隔离证明缓存命中率解释了全部变化。

4. **再将量化逐元素除法改为复用标量倒数。** 增量1.311468×、累计1.363502×。

   ```diff
   - q_float = tl.div_rn(y, scale)
   + inv_scale = tl.div_rn(1.0, scale)
   + q_float = y * inv_scale
   ```

   每行共用一个scale，把逐元素精确除法改成一次标量倒数与向量乘法，减少重复除法展开及其依赖。浮点舍入顺序变化已按既定合同检查：Q允许相对FP64最多差1 code，并同时限制scale和重构误差；不能将其称为INT8逐位等价。

5. **再提前写出Z（最终版）。** 增量1.050839×、累计1.433742×。

   ```diff
   z = x.to(tl.float32) + r.to(tl.float32)
   + tl.store(Z + offsets, z, mask, cache_modifier=".cs")
     # 随后完成统计归约、scale与Q计算
   - tl.store(Z + offsets, z, mask, cache_modifier=".cs")
   ```

   Z只依赖残差加法，不必等量化完成再写。提前store有机会缩短z的存活范围，并将写出与后续统计计算穿插，改善寄存器压力与调度；是否具体来自哪项硬件变化尚未单独量化。输入输出无别名保证该提前写出合法。


条件收益不能相加。增量相对前一版本，累计相对原始基线，各项存在依赖和交互。

因式分解是联合统计的前提。.cs加入时平均仅约0.2%–0.3%，不单独宣称稳定收益。Z精确，scale对FP64 rtol=3e-5/atol=1e-9，Q允许最多差1 code并检查重构误差，不声称INT8逐位等价。

全部时间、加速比和方法收益使用同一组原始配对样本；冻结最终选择不变。新增中间消融未全部重跑sanitizer，最终版沿用已有通过记录。
