# var_mean TTIR 优化

来源：FlagGems 的方差与均值行归约实现。固定 BLOCK_N=1024，保留 int64 行索引语义。基线采用先求均值、再求中心化平方和的两遍算法；两版经相同 Triton 原生后端编译。 上游源码：[VarMean](https://github.com/flagos-ai/FlagGems/blob/ef8aea78fed8321c3e02a15bf31e847cd0579e4f/src/flag_gems/ops/var_mean.py)（链接固定到实验使用版本）。

环境：官方Triton3.7.0/H100，连续FP32输入输出、最后一维按行归约，4 warps / 3 stages / 1 CTA。M∈{1,17,128,1024,4096}，N∈{128,512,1040,4096,8192,16384}，correction=1，7轮20ms。预分配CUDA graph设备时间，不含分配、编译和CPU launch。

**最终平均加速比：算术平均1.370951×，几何平均1.341165×。** 共30个shape，A级证据。

优化方法与性能提升：

1. **短行使用单tile并复用输入。** 单独1.1443×。

   ```diff
   - # 用循环分别加载输入，先求均值再求中心化平方和
   + # N<=128/512/1024分别选择WIDTH=128/512/1024
   + cols = tl.arange(0, WIDTH)
   + x = tl.load(X + row_base + cols, cols < N, other=0)
   + mean = tl.sum(x, 0) / N
   + centered = tl.where(cols < N, x - mean, 0.0)
   + variance = tl.sum(centered * centered, 0) / (N - correction)
   ```

   一次加载的数据同时用于均值和方差，减少短行的重复访存、循环控制和多余向量位置。中心化方差公式保留，未改成更易发生抵消误差的E[x²]-E[x]²；长行仍使用原1024宽循环。

2. **向编译器提供N为16倍数的对齐信息。** 单独1.2909×。

   ```diff
   - @triton.jit(do_not_specialize=["M", "N", "correction"])
   + @triton.jit(do_not_specialize=["M", "correction"])
     def row_kernel(X, Y, N, ...):
         # N仍是运行时参数，合法输入共享N%16==0这一对齐类别
         ...
   ```

   行stride可被16整除，使编译器能够保留行首对齐信息并选择更宽的向量加载，降低访存指令开销。这里展示允许N参与JIT对齐特化的写法；实验曾验证，简单在入口写tl.multiple_of(N,16)可能被丢弃，不能只凭提示出现在源码里就认定向量化已生效。

3. **组合短行复用与对齐信息。** 在短行版本上加入对齐信息，增量1.1721×、消融累计1.3416×。

   ```diff
   - # 只使用短行单tile分支
   + # 短行单tile分支 + 保留N的16整除对齐类别
     if N <= 128:
         short_row(..., WIDTH=128)
     elif N <= 512:
         short_row(..., WIDTH=512)
     elif N <= 1024:
         short_row(..., WIDTH=1024)
   ```

   两种变化分别减少短行工作量、改善加载表达，组合后才形成最终选择。单项收益存在交互，不做百分比相加；此处消融与前表的晋升验证是不同会话，未混算平均。

4. **缩窄长行循环的对照。** 单独1.1658×，但加入最终组合仅0.9665×，耗时增加3.46%，未采用。

   ```diff
   - for off in range(0, N, 1024):
   -     cols = off + tl.arange(0, 1024)
   + for off in range(0, N, 256):
   +     cols = off + tl.arange(0, 256)
   ```

   缩小累加向量可能降低活跃状态，但同时将长行循环次数增加到原来的四倍。在已经采用短行分派与对齐信息的上下文中，新增循环和加载代价超过收益，说明寄存器更省并非充分条件。

数值、编译链与memcheck/racecheck通过。支持连续FP32、1≤M≤4096、N为16倍数且≤16384、correction=0/1，无别名；不覆盖非连续、NaN/Inf或全张量两阶段路径。
