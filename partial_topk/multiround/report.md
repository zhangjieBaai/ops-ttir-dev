证据：[冻结选择](r5/selection.json)、[主测](r5/results/main/results.json)、[独立复测](r5/results/repeat/results.json)。

r3 计划原文将第二轮 parent 误称为全向量 packed64，已在计划末尾保留回顾性更正。实际 parent 使用全向量 uint32 max 加 i32 min-index；r3 再将这两次归约分组，只对组胜者引入 uint64 packed 归约。实验代码和数值不受这处文字更正影响。

r5 证明条件来自本次冻结矩阵：完整 local tile 含 1024 个有限值，K≤16；merge 有至少 K 个有效有限候选。仅完整且对应 merge 长度为二次幂的映射移除 load mask；N=65537 的尾块保留保护和耗尽哨兵。merge 的第二维 grid 恒为 1，可把该维 program_id 替换为 0。

r5 采用的简化是对现有合同特化，不适用于任意新 N、NaN/Inf 或每块有效值不足 K 的输入。输出按数值精确比较，稳定索引精确；+0/-0 等价，不承诺保留输入零的位型。

## 能否用公开 Triton 表达

可以。分组归约可用 `reshape`、`tl.max`/`tl.min` 和 uint64 key；批量输出可用 `join`/`trans`/`reshape` 后 `tl.store`。r5 可用 `tl.constexpr` 分支只在已证明完整的映射省略 mask，按固定 grid 使用 chunk=0，并删除不可能触发的哨兵分支。零规范化可用整数 bitcast、按位运算和 `tl.where`。本轮只实测 TTIR，尚未实测 r3–r5 源码回写的性能或 `.text` 一致性。

## 验证、计时与范围

环境为官方 Triton 3.7.0、PyTorch 2.12.0+cu130、H100 80GB，独占 GPU7，自动频率。保持原 grid、编译配置、阶段数和工作区，未重新 autotune。正式主测与复测使用 baseline/第二轮 anchor/当前 parent/候选四路同输入随机交错计时。主测 7 轮 seed42、独立复测 5 轮 seed123，每轮 `do_bench_cudagraph(rep=20ms)`；初筛 3 轮 rep10ms。输入分配前设置 shape 派生 seed 并记录输入哈希。

每轮完整矩阵的源码 baseline→TTIR 文件入口 LLVM/PTX/cubin 一致；这项一致性属于 baseline pipeline，不等于新候选已有源码回写验证。所有阶段产物、非空 ELF `.text` 和最终选择哈希均已重新核对。

累计保留 15600 项版本×输入分布检查；三轮各一次 memcheck 与 racecheck，共六次，均 0 errors、racecheck 0 warnings。这些是重复执行的检查记录，不是同等数量的独立 shape。

数值覆盖需区分行数：normal 分布在初筛/主测/复测使用原完整 M；其他压力分布使用 min(M,2) 行。sanitizer 的所有分布使用 min(M,2) 行，覆盖全部 30 个冻结 kernel 映射及其 N/K，没有在 sanitizer 下运行每个原始完整 M。

覆盖 normal、全相等、整数 ties、±0、单调输入、正/负 subnormal、最低有限值；稳定索引、数值输出、canary 与输入未改写全部通过。小行输入另对 CPU FP64 stable sort 检查。
