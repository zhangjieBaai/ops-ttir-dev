# 大 N Partial Top-K TTIR 优化

来源：采用 FlagGems 分块重复选择思路建立的两阶段研究基线。每 1024 个输入先保留 K 项，再从局部候选中选择全局 Top-K；并非生产实现的原样提取，也不使用全排序作为基线。 参考源码：[分块 Top-K](https://github.com/flagos-ai/FlagGems/blob/ef8aea78fed8321c3e02a15bf31e847cd0579e4f/src/flag_gems/ops/topk.py)（链接固定到实验使用版本）。

环境：官方Triton3.7.0，H100，连续有限FP32，K=8/16、chunk1024，4 warps / 3 stages / 1 CTA，无逐点autotune。保留两kernel、workspace、ABI/grid，计入完整local＋merge。预分配CUDA graph设备计时，不含分配、编译或CPU launch，配对计时与A/A检查通过。

**最终平均加速比：算术平均1.278042×，几何平均1.275797×。** 覆盖全部30个shape，A级性能证据。

优化方法与性能提升：

1. **FP32 max改为每轮重算有序uint32 key（负结果）。** 增量0.956820×、累计0.956820×。

   ```diff
   - best = tl.max(values, 0)
   + bits = values.to(tl.int32, bitcast=True)
   + keys = (bits ^ ((bits >> 31) | -2147483648)).to(tl.uint32)
   + best_key = tl.max(keys, 0)
     # 该初版在每次K选择时都重新编码
   ```

   有序整数key允许用uint32 max表达分数选择，但每轮重新编码增加位运算和状态转换，抵消了可能的归约收益。本项回退照实保留，不把“整数归约可用”当作已经加速的证明。

2. **再把key编码移到循环外、携带key状态。** 增量1.117830×、累计1.069569×。

   ```diff
   - for step in range(K):
   -     keys = ordered_key(values)
   + values = tl.where(values == 0.0, 0.0, values)
   + keys = ordered_key(values)
   + for step in range(K):
         best_key = tl.max(keys, 0)
   +     keys = tl.where(ids == best_id, 8388607, keys)
   ```

   ordered_key按上一项的位运算定义，将编码移出循环并直接携带key状态，省去K轮重复的FP32到整数顺序表示转换。±0先归一化，已选元素置为-inf对应的有序key；最小原始index tie规则保持不变。

3. **再固定原始ids，去掉ids循环状态。** 增量1.110134×、累计1.187225×。

   ```diff
   keys = tl.where(ids == best_id, 8388607, keys)
   - ids = tl.where(ids == best_id, 2147483647, ids)
   + # ids保持原值；移除由keys中的哨兵状态表示
   ```

   索引本身不需要随每轮改写，固定ids可以减少循环携带向量及每轮select。短尾块耗尽后的-inf与INT_MAX保护仍保留，避免padding候选干扰全局稳定排序；不能只删更新而忽略哨兵语义。

4. **再静态展开K次选择。** 增量1.015756×、累计1.205880×。

   ```diff
   - for step in range(K):
   + for step in tl.static_range(K):
         # 固定K=8/16，按原顺序执行选择和状态更新
   ```

   展开固定K使迭代常量和状态传递对编译器可见，减少循环控制并提供跨迭代调度空间。选择仍有前后依赖，不是把K次选择并行化；代码和活跃状态也可能增大。

5. **再用有限输入/完整tile合同简化mask和耗尽判断。** 增量1.022197×、累计1.232743×。

   ```diff
   - values = tl.load(X + offsets, offsets < N, other=-float("inf"))
   + # 仅在合同证明本stage所有输入lane都有效时
   + values = tl.load(X + offsets)
     # N=65537等尾块路径继续使用mask和耗尽保护
   ```

   利用完整tile、固定grid和至少K个有限候选的前提，删除恒真mask及不可能触发的部分耗尽判断，减少谓词/选择状态。尾块的保护继续保留，不将某个整齐shape的合法删除推广到全部N。

6. **merge再改成已排序局部列表的头部归并。** 增量1.030203×、累计1.269838×。

   ```diff
   - # merge每轮在CHUNKS*K个候选上做选择
   + cursor = tl.full((CHUNKS_PAD,), 0, tl.int32)
   + head = tl.load(V + chunk_offsets * K, valid_chunk, other=-float("inf"))
   + # 每轮只比较各列表head，选中后推进该列表cursor并加载下一项
   ```

   local输出每个chunk的有序K列表，因此未消费元素都不大于当前头部；只比较各列表head即可选择全局下一项。merge逻辑宽度由CHUNKS×K缩到约CHUNKS，但会新增cursor依赖和后续小加载。收益由完整local+merge两kernel计时确认，不适用于任意未排序workspace。

7. **头部选择再用packed uint64稳定比较（最终版）。** 增量1.004750×、累计1.275797×。

   ```diff
   - best_key = tl.max(head_key, 0)
   - best_id = tl.min(tl.where(head_key == best_key, head_id, 2147483647), 0)
   + packed = (head_key.to(tl.uint64) << 32) | (2147483647 - head_id).to(tl.uint64)
   + winner = tl.max(packed, 0)
   + best_id = 2147483647 - (winner & 0xFFFFFFFF).to(tl.int32)
   ```

   高32位编码值顺序，低32位反向编码原始index，使一次uint64 max同时表达最大值和最小index优先。它以更宽状态和64位归约代价换掉第二次min归约，不能仅凭归约次数就断言更快。当前增量约0.48%，不单独宣称已隔离出稳定硬件收益；耗尽和无效头部仍保留保护。


条件收益不能相加。增量相对前一版本，累计相对原始基线，各项存在依赖和交互。

每轮重算key的回退照实保留；packed头部比较相对uint32版本约0.4%–0.5%，不单独宣称可靠收益。indices严格精确、value数值精确，±0等价；头部归并依赖局部列表有序。

全部时间、加速比和方法收益使用同一组原始配对样本；冻结最终选择不变。新增中间消融未全部重跑sanitizer，最终版沿用已有通过记录。
