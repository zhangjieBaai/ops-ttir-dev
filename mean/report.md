# Mean TTIR 优化

来源：FlagGems 的 mean_dim 实现。冻结原始启发式配置后导出 TTIR，连续输入视为 [M,N,K]，沿 N 取均值；只修改 K≥1024 的向量循环路径。基线的源码编译与 TTIR 编译产物一致。 上游源码：[Mean](https://github.com/flagos-ai/FlagGems/blob/ef8aea78fed8321c3e02a15bf31e847cd0579e4f/src/flag_gems/ops/mean.py)（链接固定到实验使用版本）。

环境：官方Triton3.7.0/H100，FP16输入输出、FP32累加。向量路径BLOCK_SIZE_K=128、VEC_SIZE=8，8 warps / 3 stages / 1 CTA；其余路径/grid不变。30点，另有12个边界正确性点，7轮20ms。预分配CUDA graph设备时间，不含分配、编译和CPU launch。

优化方法与性能提升：

1. **扁平化向量状态并使用32位地址索引。** 累计1.1008×。

   ```diff
   - lanes = tl.arange(0, 128)[:, None] * 8 + tl.arange(0, 8)[None, :]
   - row = tl.program_id(0).to(tl.int64)
   + lanes = tl.arange(0, 1024)
   + row = tl.program_id(0).to(tl.int32)
   ```

   128×8与1×1024覆盖相同的逻辑输出元素，扁平化改变编译器处理布局和索引的方式；在已验证的地址范围内使用i32，减少64位整数地址中间量及相关指令。两项按组合测得收益，不能将全部提升分配给扁平化；仅改变形状也可能得到相同机器码。

2. **展开16行预加载并保留原累加顺序。** 组合增量1.2815×、累计1.4106×。

   ```diff
   - for n in range(N):
   -     acc += tl.load(X + row_base + n * K + lanes, mask, other=0).to(tl.float32)
   + for n0 in range(0, N, 16):
   +     # 先预加载v0…v15，再按原来的n顺序累加
   +     v0 = tl.load(X + row_base + n0 * K + lanes, mask0, other=0)
   +     v1 = tl.load(X + row_base + (n0 + 1) * K + lanes, mask1, other=0)
   +     # 同样预加载v2…v15，尾部均保留n0+j<N的掩码
   +     acc = acc + v0.to(tl.float32)
   +     acc = acc + v1.to(tl.float32)
   +     # 再依次累加v2…v15
   ```

   提前发出多个独立加载，为调度器提供更多可重叠的访存请求，减少逐行“加载后立即等待再累加”的依赖链影响。N<8保留原路径，单列尾块采用256×1的N方向归约，避免小输入承担展开成本。展开可能提高寄存器压力；当前增益包含展开、短N分支和尾列策略，没有分别量化三者。实际修改的18个向量路径点几何加速1.7743×，其余12点实现不变。

全部数值、编译链和memcheck/racecheck检查通过。固定30点均曾用于调优和回归，不能外推任意输入。
