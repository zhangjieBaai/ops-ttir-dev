## 改动与契约

最终候选为 `r2_combo16_v2`，每组写一次的 `r2_final.ttir` 与它字节相同。第一轮 `optimized.ttir`、原始 baseline、源码快照、baseline.json 和第一轮报告均未改写。26 个原始 TTIR/配置组、42 个输入映射、签名、grid、warps、完整 backend options、容差均沿用原契约。

K≥1024 的主路径将每次循环展开为16行加载，然后按原顺序累加。N<8 保留第一轮路径；当该 CTA 的剩余输出恰好为一列时，使用256×1的 N 方向分块归约。后者保持相同 CTA 和输出归属，不增加 kernel 或工作区，但改变尾列的浮点归约顺序。K<1024 的两条路径与原始 baseline 保持字节相同。分支均根据运行时 N 和 K/CTA位置决定，没有按测试 shape 查表。

所有候选直接由 TTIR 文本构建；未生成候选 Python kernel、修改 TTGIR/LLVM/PTX/cubin，也未替换 binary 或 launch metadata。编译与启动继续使用 common.compile_ir/common.launch。这些循环展开与归约策略也可用 Triton 语法表达，不声称为 TTIR 独有。
